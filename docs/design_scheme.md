## 学生基础与实验约束

- 认为所有人都只是学习过操作系统的概念性知识，无任何操作系统开发相关的经验或知识
- 按以下能力边界设计教学和验收：

### 可以假定学生掌握的内容

- 已经学习过操作系统课程，了解进程、内存、文件和用户态、内核态等基本概念。
- 会编写 C 语言程序。
- 能按照指导修改代码、复制命令、运行程序和查看输出。

### 不能假定学生掌握的内容

- Linux 终端、Git、Makefile 和交叉编译工具链。
- QEMU、GDB、readelf、objdump、nm 等工具。
- 入口汇编、链接器脚本、可执行文件的加载和内存布局。
- RISC-V 指令、CSR、陷阱入口和特权级切换的具体实现。
- 编码智能体；教学支持不能依赖学生会使用 Codex、Claude Code 或 Cursor。

## 设计原则

### 可完成性约束

- 面向上文描述的学生基础设计必做实验，通过参考实现和学生试做验证可完成性。
- 工作量按不借助 AI 工具、由学生独立阅读和手写实现估算；教学材料和必做路线不能以使用 AI 为前提。

### 学生主要实现操作系统功能

- 与教学目标无关的一次性工程工作由我们完成；实际实现内核必须接触的底层知识由指导书讲解。
- 不让一次性的工程配置占用主要实验时间。
- 必须接触的底层知识由指导书解释，不要求学生自行查齐所有资料。
- 提供启动、构建、调试和测试所需的代码，不提供需要学生实现的内核功能
- 不指定学生的内核目录结构、内部数据结构和具体实现算法。round-robin 的可观察轮转规则属于本课明确要求，队列和状态的内部表示由学生决定。
- 所有测试程序，只定义要被验收的接口格式和语义，不定义内核的结构

### 公共基础完成后，尽量支持模块独立推进

- 每个模块列明前置条件。满足前置条件后，可以单独运行相应测试；不承诺公共基础完成后所有模块都互不依赖。
- 模块测试按依赖验收，组合测试和完整内核另做集成验收。
- 教学讲解可以按顺序展开，不把讲解顺序变成学生必须遵守的开发顺序。
- 尽可能保证任务的独立性和可并行性，只在必要的时候做线性的任务安排

### 要求必须能够被测试

- 每项必做功能都提供容易运行的测试。
- 测试只检查 API/ABI 的行为，不检查学生是否采用指定内部实现。
- 同时测试正常行为、边界输入和失败后的状态。
- 不用未公开的功能要求扣分。
- 测试失败应帮助学生定位问题，不能只输出一个 FAIL。

### 时间与工作量

- 采用持续、自主推进方式，不设置统一的每日课表或固定答疑日，并给阅读、调试和其他课程留出时间。
- 按单个学生独立完成设计，不依赖多人分工。
- 学生实现代码预计约 3000 至 4000 行。
- 阅读加编码暂以不超过 48 小时作为可行性预算；环境配置、调试和集成单独记录，并纳入整体工作量评估。
- 行数和时间先作为预算，通过参考实现和试做验证，不作为评分指标。

### 评价不能增加无关负担

- 所有评分标准都不能惩罚认真做事的学生，哪怕会漏掉直接完全通过 AI 工具完成实验或者抄袭别人的代码的学生
- 集成单独评价。
- 不以代码行数、实现速度或 AI 检测结果判断成绩。
- 不阻止学生使用 AI 工具。
- 不为防止少数学生完全依赖 AI，给认真完成实验的学生增加大量额外工作。

## 一些重要问题的决定

### 定义“从零开始”

学生在可启动、可调试的工程中，自行设计并实现操作系统核心功能。

我们提供入口汇编、链接器脚本、启动页表、Makefile、工具链配置以及启动 QEMU、连接 GDB、嵌入资源和运行测试的脚本。内核符号从最初提供的工程开始就位于规定的高半虚拟地址，学生不承担从低地址迁移内核的任务。框架在物理入口使用独立临时栈，激活我们提供的启动页表并跳转到高半入口，随后清理普通 BSS、设置正式内核栈和 gp、初始化预留的内核堆，最后调用学生的 C 或 Rust 内核入口。启动页表同时为启动阶段和基础设备访问保留 spec 明确列出的低地址恒等映射；这些映射的范围和权限由我们固定并验证。

平台使用固定版本的 QEMU、固定启动参数和固定机器配置。我们从冻结配置中整理学生实际需要的信息，提供人类可读的机器规范以及 C/Rust 平台常量，直接列出 RAM 范围、UART 和 RTC 的 MMIO 基址、寄存器偏移、访问宽度、必要状态位及计时频率等属性。学生理解 MMIO 的概念并使用这些公开信息，不承担机器描述数据的发现、解析或转换。资源范围由链接符号取得，测试元数据不代替平台常量。对于 Rust 代码，还需要提供 panic 处理函数。

UART、陷阱入口、上下文切换、最小 ELF 解析和被验收的核心模块由学生实现。指导书可以给出 printf、println 和 CSR 的参考用法。SBI 调用适配与内核堆由工程提供可用实现，学生学习接口及使用条件；spec 规定外部行为，不强制学生采用指定库或内部封装。课程只使用严格裁剪的 RV64 静态 `ET_EXEC` ELF：装载只读取 ELF 头、程序头和 `PT_LOAD` 段，支持代码、数据、BSS 和固定用户栈；不要求动态链接、解释器、重定位、PIE、TLS 或按节装载。指导书明确 ELF 的完整格式很复杂，本实验只实现建立用户任务所需的核心子集。

参考内核使用 Rust，先用于内部验证课程可行性。是否向学生开放后续再决定，不能把参考实现默认视为学生工程的一部分。

### OpenSBI 服务与调用适配

本课使用 OpenSBI 提供的 SBI 服务，必用范围为 SRST 关机和 TIME 计时器。我们提供 C/Rust 调用适配、构建接入和示例，学生负责调用时机及结果处理。Rust 可采用 sbi-rt，C 提供对应的薄封装；具体依赖版本随工程固定。适配层只完成参数、寄存器和返回值转换，不代替陷阱处理、时间管理或调度。

指导书介绍 SBI 规范与 OpenSBI 实现的关系，区分用户程序向 S 态内核发起的系统调用和 S 态内核向固件发起的 SBI 调用。BASE 版本查询及扩展探测作为环境检查示例，由我们验证课程固件支持 TIME 和 SRST 关机，不增加独立评分任务。重启和其他扩展仅按需介绍；UART 仍由学生实现，不用 SBI 控制台代替该实验。

关机用于结束系统运行和早期测试，不要求新增用户关机调用。普通用户任务 exit 只结束该任务；前台程序结束后应返回 shell。TIME 用于设置下一次计时器事件，时间片、睡眠队列、中断使能和重设计时器仍由学生负责。

### 内核堆的提供边界

工程提供固定容量的可用内核堆，包括 C 分配释放接口、Rust 全局分配器接入、初始化与同步适配。学生只需理解和使用，不要求实现堆分配算法，不单独设置算法评分。具体分配器和容量由参考实现验证后固定，可采用适合裸机的现成库；C 学生不必接入 Rust 才能使用堆。

堆使用链接脚本预留的对齐内存，计入整个内核加载映像的保留范围，在进入学生主函数前初始化，不依赖学生的物理页分配器，也不要求运行期间扩容。学生仍自行实现物理页分配、页表和用户 `brk`，不能用提供的对象分配接口替代这些被验收的核心功能。内核接口沿用 Linux RISC-V 64 的 `brk` 系统调用，用户库在其上提供 `sbrk` 包装；`mmap/munmap` 不列入基础必做。

学生在物理页管理中排除内核堆所在保留区。框架在高半启动页表生效后初始化堆；学生更换运行期页表时保持堆及已有对象的高半虚拟地址有效。指导书给出固定内核映射要求，说明内核堆、栈、物理页池和用户堆的区别。

堆的对齐、释放复用、容量耗尽及同步由我们验证。分配器临界区应具备适合单核抢占的中断保护，退出时恢复原中断状态；提供实现不在临界区内主动调度、阻塞或递归分配。学生学习这些使用限制，不承担分配器锁和中断保护的实现任务。spec 明确可用接口、容量、地址范围、分配失败行为及 Rust 容器的耗尽处理，不把内核堆耗尽与用户内存申请失败混为一谈。

### 关于驱动程序的实现边界

设备相关的必做任务为阅读我们提供的人类可读机器规范，并通过最小 UART 驱动理解 MMIO、设备寄存器和输入输出。我们直接提供所需设备基址、寄存器地址或偏移、访问宽度和属性值。其他设备驱动由我们提供实现或第三方依赖，学生只完成公开的内核接入任务，不承担平台发现、驱动选型和移植。

### 关于文件系统的实现边界

基础版本使用课程自定义的最简内存文件系统。构建工具将文件系统 img 转换为具有 WRITE、ALLOC、LOAD 属性的数据段，链接到指定且页对齐的 RAM 范围；链接器分别导出 CPU 访问使用的 `__ramdisk_start/__ramdisk_end` 和物理保留使用的 `__ramdisk_phys_start/__ramdisk_phys_end`。内核直接读写该范围，不在启动时复制镜像。修改只在本次 QEMU 运行期间有效，重新启动后从原始 img 恢复。

文件系统采用扁平名称空间、固定文件项数量、固定名称长度和固定单文件容量。镜像依次由文件系统头、固定长度的文件项表、对齐填充和每项对应的固定数据槽组成。文件系统头记录魔数、版本、镜像大小、文件项数量、名称上限、单文件容量、文件项大小及各区域偏移；文件项记录有效标记、名称长度、文件长度和名称。数据槽起点按 `data_offset + index * slot_size` 计算，不在文件项中保存可变块链或动态位置。文件系统头和文件项优先设计为便于手算的固定大小，全部多字节字段采用小端编码；学生按公开字段偏移读写，不依赖 C/Rust 原生结构体的隐含填充。具体字段宽度、保留字段、对齐、容量和魔数由 spec 固定。

固定数据槽以空间换取实现简单，因此不要求学生实现目录树、空闲块表、簇链、动态扩容、碎片整理、日志或崩溃恢复。文件项数量和单文件容量不在设计阶段凭经验写死：我们先构建并裁剪两种语言所需的用户程序，按最大必需 ELF 和基础数据文件确定单文件容量，并为学生创建文件保留空项和容量余量。图形应用、mGBA ROM 等选做资源不得反向抬高基础规格；需要时使用单独的选做镜像或配置。

我们依据同一份格式规范维护两类独立实现：宿主侧镜像制作、检查和查看工具，以及参考内核中的完整文件系统实现。构建工具读取显式文件清单，将 shell、编辑器、cat、rm 和必要数据写入初始镜像，拒绝重名、超长名称、超出单文件容量和超出文件项数量的输入，并在链接前执行一致性检查。参考内核实际从该镜像装载用户程序并完成四个文件操作，用于验证格式、系统调用和综合场景；这些参考实现不作为学生工程中的文件系统后端。

学生依据公开格式实现初始化、名称查找和四个操作：创建、删除、整文件读取和整文件覆盖写入。创建得到长度为零的文件并确定性地使用编号最小的空闲项；删除释放对应文件项，不要求擦除整个数据槽，但旧内容不得再通过接口读取；读取在缓冲区足够时复制完整文件并返回长度；写入只覆盖已经存在的文件，用给定内容替换全部内容并更新长度。名称重复、文件不存在、表满、内容超过固定容量、缓冲区不足和用户指针非法时按 spec 返回错误且不产生可观察的部分修改。基础任务不包含目录、枚举、打开/关闭、文件描述符、独立打开偏移、追加、局部写入、截断、权限、挂载、多后端或通用 VFS。

内核内部允许通过名称查找取得文件数据起点和长度。由于文件内容在固定数据槽中连续存放，ELF 装载器可以直接从该只读视图校验 ELF 并把 `PT_LOAD` 段复制到用户页面，无需先将整个文件复制到内核堆。该视图只在当前内核操作期间使用，不跨文件修改长期保存，也不形成打开文件对象、引用计数或额外用户系统调用。

### 关于内存的实现边界

基础路线使用 Sv39 和 4 KiB 页，实现物理页管理、三级页表、独立用户地址空间、用户与内核隔离以及立即分配的 `brk`。用户空间位于低半区，内核运行映射位于高半区；具体虚拟地址布局、权限和保留区域由 spec 固定。缺页恢复或 demand paging、大页和 `mmap/munmap` 为选做，swap/page replacement 不要求。

内核从工程初始状态起就使用固定的高半 VMA 和正确的物理 LMA。我们提供完整的链接器脚本、低地址物理入口、临时栈、静态启动页表和激活页表的入口汇编，并验证跳转、BSS 清零、正式栈、gp、堆和链接资源在学生入口前均可使用。学生学习 VMA、LMA、Sv39 canonical address 和高低半区约定，但不修改内核虚拟偏移，也不自行设计或生成 boot 期页表。

启动页表使用 4 KiB 页，同时映射高半内核以及课程规定的低地址恒等映射。恒等映射仅覆盖启动过渡所需范围和公开的 MMIO 区域，采用最小必要权限且 U=0；不把全部 RAM 长期恒等映射。最终运行期页表必须保留学生实际使用的 MMIO 映射，是否继续保留其他启动恒等映射由 spec 规定。启动页表数据位于独立已初始化段，不被普通 BSS 清零覆盖；ramdisk 数据段同样不参与 BSS 清零。页表项 PPN 和 `satp` 根页号均使用物理地址。

指导书同时讲解两种运行期页表方案，学生任选，均属于满足基础要求的合法实现：

- 方案 A：每个用户页表包含相同的高半内核映射，内核映射 U=0；用户陷入时可以保持 satp，切换到内核栈后处理。
- 方案 B：独立内核页表，通过 trampoline 在用户页表与内核页表间切换。指导书说明跳板在两张页表中使用相同虚拟地址映射同一物理代码页，以及切换前可访问的 trap 保存区、satp/sfence.vma、栈和返回路径；跳板与保存区不得允许 U 态访问。
- 两种方案都必须保证用户隔离、高半内核地址有效和正确返回。用户复制可通过软件页表遍历访问物理页的内核映射；不能假定切到内核页表后仍可直接解引用用户虚拟地址。测试不读取私有页表组织或强制其中一种方案。

### 关于实现质量的要求

要求公开功能和调度语义正确，不要求性能优化或固定帧率。调度器固定采用所有普通任务时间片相等的单核 round-robin；不引入 FPRR、动态优先级或变长时间片。计时器抢占、睡眠和输入响应仍须正常工作，不能以“不要求性能”为由忽略这些行为。

基础调度必须支持用户态计算过程中的计时器抢占，允许内核态不被计时器抢占；阻塞操作主动交出 CPU，普通内核操作须在有限时间内完成，不得因等待输入阻止其他就绪任务运行。指导书明确中断状态、临界区和阻塞切换的衔接，不要求任意内核位置重入。

### 关于测试程序运行环境的假设

所有测试在单核环境运行，每个用户程序只有一个执行线程。只有调度测试和明确标注的组合测试要求多个用户任务并发；早期内核测试、最小用户 ELF、基本内存和文件测试不假定调度器已经完成。

### 自定义 ABI 设计方式    【我们统一规定调用号和参数，不让学生自行分配；能对应 Linux 的接口沿用其 ABI 并限定支持范围，共享消息队列和 spawn 使用课程调用号。】

对于能对应 Linux 语义的调用，使用 Linux RISC-V 64 位的系统调用号、内核参数列表、返回值、错误码数值和跨边界结构体布局。这里参照的是内核 ABI，不是 libc 的函数原型或 errno 封装。具体依据的 UAPI 版本随课程工具链一同记录。

裁剪通过明确支持的操作、标志和参数范围完成。保留部分沿用对应 Linux 定义，结构体不因暂时不用某个字段就改小；未使用字段如何初始化、未支持请求如何拒绝，由 spec 明确。参数可以要求固定取值，但不能用相同编号悄悄改成另一种操作。

最简文件系统的四个操作与 Linux 的 fd 接口不具有相同语义，使用课程调用号，分别按文件名完成创建、删除、整文件读取和整文件覆盖写入。名称、缓冲区、长度、返回值和错误行为由 ABI 总表固定，不冒用 `openat/read/write/unlinkat` 等 Linux 调用号。标准输入输出仍使用课程裁剪后的 Linux `read/write` 语义，两类接口在名称和调用号上明确区分。

原始 brk 成功时返回新的 break，申请失败时返回当前 break，而不是套用通常的负 errno 规则。用户库 sbrk 成功返回原 break，并按用户库约定转换失败结果；两层分别测试。

课程不承诺 Linux 二进制兼容，也不引入完整 Linux 功能。spec 逐项列明有效参数、标志组合和不支持时的错误返回；范围内遵循公布语义，范围外明确拒绝。共享消息队列采用多发送者、多接收者的有界 FIFO 队列语义，但由于不实现完整的 Linux SysV/POSIX 消息类型、命名、权限和控制接口，仍使用课程调用号，不冒用对应 Linux 编号；spawn 同样使用课程调用号，不冒用 execve 编号。对 Linux 没有对应语义的接口，使用 1024 + n 分配课程调用号，由 spec 统一登记并检查冲突。例如创建并装载新任务的接口不能直接冒用 execve 的编号；新增调用的参数和结果结构单独规定。

这一决定替代旧版 spec 的自定义编号、错误码和结构体方案。课程发布一张唯一且冻结的 ABI 总表，明确每个调用号、寄存器参数、返回值、错误码、结构体布局和裁剪语义；学生不得自行分配或修改调用号。后续应先更新 ABI 总表、用户库、测试及应用适配，再生成配套 ELF；旧产物不能直接作为本版验收包。

## 课设目标

### 学生需要完成的基础任务

- 在提供的工程框架中实现一个单核 RISC-V 内核，支持 Sv39 虚拟内存和独立用户地址空间。
- 实现 UART 输入输出、陷阱入口与现场保存、用户态与内核态切换、内存管理、ELF 校验与装载、任务管理和课程最简文件系统。
- 正确处理课程必需的 U-mode `ecall` 和 supervisor timer interrupt，并能根据 `scause` 区分中断、异常及具体 cause code。对其他未支持的 trap cause，学生自行选择并公开处理策略；可以终止当前任务、报告后 panic 或关闭系统，但不得静默忽略、错误返回原指令或形成无限重复陷入。缺页恢复不属于基础要求。
- 实现等时间片 round-robin 抢占、主动让出、睡眠和退出。
- 实现约定的课程 ABI：对应调用沿用 Linux RISC-V 64 位定义并裁剪支持范围，课程新增调用单独编号；不承诺完整 Linux 二进制兼容。
- 先完成最小用户程序运行环境，后续模块主要在学生自己的内核中通过用户程序测试。
- 能同时运行多个用户程序。使用不主动让出的计算程序、周期输出程序和睡眠程序检查调度与隔离，不能只用前台程序顺序执行代替并发验收。
- 实现消息队列作为本课唯一必做 IPC 原语。消息队列是独立的共享内核对象，采用固定消息大小和固定容量，支持多发送者、多接收者、非阻塞发送、阻塞接收、唤醒、显式删除与退出清理；每条消息只由一个接收者取走。shell 使用一个专用共享队列接收内核生成的前台任务完成事件。
- 当前基础综合场景为：内核启动后进入 shell，根据扁平文件名启动文本编辑器，创建或读取文件、覆盖写入并保存；编辑器退出后返回 shell，再运行 `cat` 读取内容并用 `rm` 删除文件。
- shell、编辑器、cat、rm 由我们提供和适配。cat 和 rm 作为可执行文件存在，不作为 shell 内置命令；基础场景不要求列举文件，因此不提供 ls。
- 完整运行配置中的程序和数据通过同一个最简文件系统访问，文件修改只要求在本次运行期间有效。直接嵌入 ELF 是早期测试安排，不作为完整系统的第二条程序名称查找机制。

### 已确认的选做任务    【我们将缺页恢复、大页和 mmap/munmap 列为选做；paging 按具体内容区分，Sv39 基础分页仍必做，swap/page replacement 不要求。】

- 缺页恢复或 demand paging、大页和 `mmap/munmap`。
- 接入我们提供的完整 Virtio-GPU 和 Virtio-Input 驱动，完成内核中的接口与资源管理。
- 运行我们移植的 mGBA，加载指定 ROM，显示画面并响应操作。
- 不要求声音、QEMU 重启后的存档恢复和固定帧率，运行期间能够正常操作即可。
- mGBA 移植、宿主依赖裁剪和应用侧适配由我们完成，不作为学生任务。
- 附加部分单独提供测试和指导，不能阻止基础部分验收。

### 想要达到的教学目标

- 理解内核程序的运行条件，能够使用提供的工程和调试工具开始内核开发。
- 理解设备寄存器访问，完成最小 UART 驱动。
- 理解陷阱现场保存、系统调用入口、特权级转换和执行流恢复。
- 理解物理内存、虚拟地址和用户隔离，设计自己的内存管理方式。
- 理解 Sv39 有效地址范围、高低半区约定，以及框架如何从物理入口进入高半内核。
- 理解 ELF 文件如何变成一个可执行的用户任务。
- 理解任务状态、时间片、阻塞和唤醒，实现多个用户程序的并发运行。
- 理解共享有界消息队列的创建、发送、竞争接收、阻塞、唤醒、删除和对象生命周期，并用它完成多任务通信。
- 理解最简文件系统如何用固定元数据描述文件名称、长度和数据位置，并实现创建、删除、读取和覆盖写入。
- 能根据公开测试、日志和调试信息定位错误，并解释自己的设计。

## 总体设计思路

### 从用户程序的需求确定必做功能

先确定基础用户程序和运行场景，再分析它们需要的最小内核服务。每项内核服务都要对应教学目标或基础程序的实际需求，不为了接近完整 Unix 而增加功能。

应用适配时优先裁剪与教学无关的需求。不能因为选中的编辑器需要完整终端管理，就把相关机制全部变成学生任务。应用需要的内核行为必须进入 spec 和测试，不在最终演示时突然要求。

任务安排和测试必须围绕 spec。建设期间允许依据参考实现和试做修正规范；正式发布后冻结该课程版本。必要勘误需说明影响，同步更新用户库、测试和教学材料，不追溯增加学生义务。

### spec 与实验指导书分别写什么

spec 说明输入、输出、行为、错误、资源归属和验收边界。除外部兼容要求外，不规定源文件组织、私有结构体和具体算法。

指导书是学生完成实验所需的完整学习资料，解释如何开始、为什么需要这些机制、如何实现一种容易理解的方案，以及如何检查错误。必要知识、操作步骤、参考示例和排错方法都应写入指导书，不依赖定时授课或集中答疑补齐。学生可以选择其他满足 spec 的实现。

例如，基础 `brk` 统一采用立即分配，指导书讲解一种最小实现；demand paging 作为选做另行说明。等时间片 round-robin 是本课固定要求，spec 明确其可观察轮转行为，但不规定学生内部队列的数据结构。

### 区分学习顺序与实现顺序

指导书按照学生建立内核的经历展开：运行工程、阅读机器规范、UART、外部符号、陷阱、物理页、Sv39 用户地址空间、最小 ELF 装载，随后扩展用户堆、调度、消息队列、最简文件系统和 shell，最后综合验收。

前半部分是公共基础，按顺序引导学生完成单核、单用户任务、Sv39 用户地址空间、ELF 装载和最小系统调用。框架已经在进入学生代码前建立高半内核运行环境。此时不要求调度器、消息队列、完整 `brk` 或文件系统。指导书写清观察和排错步骤，不由我们提供的运行环境替代学生的核心模块。

公共基础通过后，用户堆、调度、消息队列和最简文件系统可以按依赖分别推进。每个测试列明需要哪些已完成能力，不为消除依赖而编写可替换的参考模块。学生可提前编写其他模块，但不承诺在基础未完成时就能验收它们。

第一个测试 ELF 直接链接进内核，通过起点和长度装载。学生使用自己的页分配器和页表建立代码、数据和固定用户栈，暂不依赖文件系统、用户动态内存或命令行参数。最简文件系统完成后更换字节来源，最终按扁平文件名读取程序；带参数启动和完成消息等待在 shell 阶段补齐。

### 控制额外工作量

驱动和应用移植等部分过重时，由我们提供代码。文件系统通过固定格式和固定容量控制复杂度。核心模块过重时，减少必做范围，而不是要求学生在同样时间内完成更多功能。

课程采用持续推进，阅读加编码暂以不超过 48 小时为可行性预算，学生实现的核心代码预计约 3000 至 4000 行；参考内核按相同边界单独统计，排除框架、镜像制作工具、驱动、应用和测试代码。调试和集成时间另外记录，也必须纳入整体可完成性的判断，不能把超时都归为不计预算的调试。

- 同时保留由我们维护的脚本和简要说明，用于从干净 Ubuntu 26.04.1 LTS 重建相同环境并排查问题，而不要求学生自行安装全部依赖。

### 内存和任务

- 使用 Sv39，建立独立用户地址空间，禁止用户程序访问内核及其他任务的私有内存。
- 基础任务只实现 4 KiB 页和立即分配的 `brk`；用户库提供 `sbrk`。缺页恢复、大页和 `mmap/munmap` 为选做，swap/page replacement 不要求。
- 使用规定的低半用户空间与高半内核空间布局。框架提供高半链接、boot 页表及必要的低地址恒等映射；学生从已运行在高半地址的内核入口开始，实现通用 Sv39 页表和用户隔离。
- 实现等时间片 round-robin 抢占、让出、睡眠和退出，不要求 FPRR、动态优先级或变长时间片。
- 支持多个用户任务，不要求线程和完整进程信号机制。
- 消息队列是唯一必做 IPC 原语；不再单独要求信号量、互斥锁、共享内存或其他 IPC。采用独立共享队列对象和不透明队列 ID，要求多个任务能够同时作为发送者或接收者；基础范围仍不要求阻塞发送、消息优先级、按类型选择、超时、命名持久化、权限模型或信号量式同步。

### shell 与用户程序    【我们将 shell 限定为按扁平文件名启动带参数的前台程序；管道、重定向、后台任务、脚本和 if/for 等语法均不纳入本版。】

- shell 根据扁平文件名请求内核创建并装载用户任务，支持命令行参数。
- 基础方式为前台执行：shell 等待程序退出，随后继续接收命令。
- 程序启动失败和前台程序正常退出后，shell 应继续可用。若学生选择对某类用户 trap 进行任务级终止，则该路径也应正确恢复 shell；如果公开策略是内核 panic 或关机，则不要求在该 cause 后继续运行。
- 前台运行期间需要明确输入归属，避免 shell 和子程序同时读走串口输入；不要求完整终端作业控制。
- shell 的基本使用方式接近常见 sh，但不以完整 sh 兼容性验收。
- 不要求环境变量、管道、重定向、后台任务和 shell 脚本；不支持 `if`、`for`、变量展开、命令替换等语言结构。
- 编辑器允许简化。终端字节序列、编辑操作和屏幕刷新由我们在应用侧适配；学生只实现已公开的内核接口。

### 文件系统

- 学生实现课程自定义的最简文件系统，直接操作链接进内核的可写 ramdisk img。我们提供格式规范、初始镜像、文件清单、镜像制作与检查工具、链接边界符号以及 C/Rust 的字段访问示例，不提供已经完成的文件系统后端。
- 文件系统使用扁平名称空间和固定布局：文件系统头、固定数量的文件项、对齐填充和每项对应的固定容量数据槽。学生实现格式校验、名称查找、创建、删除、整文件读取和整文件覆盖写入。
- 基础任务没有目录、路径解析、枚举、文件描述符、打开状态、偏移、权限、挂载、多个后端、VFS 或动态空间分配。文件名只是受限长度的单个名称，不能包含路径分隔符。
- 创建空文件；删除释放文件项；读取复制完整文件；写入替换完整内容。所有失败必须保持已有元数据和文件内容不变，不要求事务、日志或断电恢复。
- 我们使用同一格式实现宿主侧工具和参考内核，初始镜像真实保存 shell、编辑器、cat、rm 及必要数据；完整配置中的用户 ELF 和数据通过该文件系统按名称读取。早期独立测试允许直接装载嵌入 ELF，复用同一 ELF 装载器；该入口只存在于相应测试配置。
- 基础任务不要求 VirtIO Block、DMA 存储、重启后持久化或磁盘故障恢复。

### 显示与输入

- 我们提供完整 Virtio-GPU/Input 驱动及 C、Rust 可用的接入方式。
- 学生负责将驱动接入自己的内核，并完成约定的用户显示和事件接口。
- 图形、输入和 mGBA 为附加部分，基础 shell 使用 UART。
- 驱动需要的分配、映射和可选中断回调必须提前列明，不能隐含要求另一套完整内核框架。优先评估轮询完成的同步接口；阻塞与否、轮询还是中断分别说明。等待设备期间如何维持调度和响应也由接入契约规定。

#### spec 要说明什么

- 外部测试函数统一使用 C ABI，公布完整函数签名、参数宽度、返回值，以及调用时需要的栈、特权级和已初始化能力。

- ramdisk 中某一镜像或字节范围表示为 `addr(ramdisk_start) + image_offset`，内核测试函数入口表示为 `addr(testcase_api_start) + function_offset`，嵌入测试 ELF 起点表示为 `addr(testcase_elf_start) + elf_offset`。文中的“符号 + offset”均表示取符号地址后按字节加偏移，不是读取符号处的数据，也不是按指针元素大小缩放。单一 ramdisk img 从该段起点开始时，image_offset 为 0。

- `testcase_api_start` 对应按框架高半内核布局链接的可执行测试代码，构建系统负责重定位、保留所需节并校验入口；不能将任意裸代码复制到其他地址后直接调用。`testcase_elf_start` 对应作为数据嵌入的用户 ELF 文件，内核高半地址不改变其内部的用户装载地址和入口，学生仍按 ELF 装载流程建立用户映射，不能直接把 ELF 文件起点当作函数调用。
- ramdisk 的位置说明用于解释镜像嵌入和最简文件系统访问。文件系统内部字段和数据槽偏移以公开格式为准，不能把链接段内的任意绝对地址写死到学生代码中。
- 弱默认实现只报告未实现。工程中未完成接口可以链接，不代表相关测试已经通过。

#### 实验指导书要编写什么

- C 中用函数声明调用外部函数，用 extern 声明外部变量或边界数组；说明声明不会自动把实现加入链接，我们提供的对象文件仍由 Makefile 接入。
- Rust 中使用 `unsafe extern "C"` 声明外部函数和符号，解释调用所需的 unsafe 边界；反向导出学生函数时，给出符合课程 Rust 版本的稳定符号名写法。

- 用链接脚本中 `__kernel_image_start = .;` 这样的语句解释边界符号：它标记一个地址，并不自动在该地址存放一个同名整数。获取边界时应取符号地址，不能读取那个位置的内容作为边界值。
- C 示例使用 extern 字节数组取得地址，再转为 uintptr_t 计算范围；Rust 示例使用外部符号的原始地址，避免为了取地址而构造引用或解引用。真正的外部数据变量另用一个例子说明。
- 先检查 end 不小于 start，再计算字节数；演示向外页对齐后，将整个内核加载范围加入保留区。RAM 总范围来自冻结的机器规范，两种信息共同用于内存初始化。
- 用 nm、readelf、链接 map 和 GDB 对照同一符号；演示 undefined reference、名字不一致、声明签名错误及把地址误读成内容时的排查步骤。
- 普通外部函数可按符号名调用；对于按资源清单提供的测试入口，演示使用 `addr(testcase_api_start) + function_offset` 取得地址，再按公布的 C ABI 签名构造函数指针调用。同步演示用 `addr(testcase_elf_start) + elf_offset` 和长度取得 ELF 字节范围，以及用 ramdisk 起始符号取得镜像范围。讲清边界、整数溢出、对齐和映射权限检查，不要求学生记住绝对地址。

### 任务 4：陷阱、现场保存与第一个系统调用    【我们保留用户 ecall 和计时器中断的必做处理，补充 scause 分类教学；未支持的 cause 由学生公开选择处理策略，不统一要求打印后 panic，缺页恢复不作必做。】

#### 想要让学生掌握什么

- 理解陷阱如何保存现场，内核如何找到原因并返回原执行流。

#### spec 要说明什么

### 任务 6：最小 ELF 校验与装载    【我们将 ELF 限定为静态 RV64 ET_EXEC，只装载 PT_LOAD，拒绝动态链接和 TLS 等复杂需求；各段按页组织且不共享页面，并在指导书中解释只读取核心子集。】

#### spec 要说明什么

- 只接受 64 位、小端、RISC-V、静态链接的 `ET_EXEC`。装载只使用 ELF Header、Program Header Table 和 `PT_LOAD`；不支持 `PT_INTERP`、`PT_DYNAMIC`、动态链接、共享库、重定位、PIE 或 TLS。
- 必须校验的头字段、文件边界、段范围、权限、入口和整数溢出。
- 课程用户 ELF 的 PT_LOAD 按 4 KiB 页组织，页对齐后的内存范围互不重叠，且与固定用户栈等区域分离；不支持段共享页面，不要求合并段权限。我们保证全部配套用户 ELF 满足该裁剪，不符合课程布局的文件明确拒绝。
- 文件长度与内存长度的处理、固定初始栈和无参数入口状态；任务 6 的阶段验收不要求变长参数打包。
- 仅 PT_LOAD 参与装载；PT_INTERP、PT_DYNAMIC、PT_TLS 明确拒绝。PT_NULL、PT_PHDR、PT_GNU_STACK 明确忽略，不由 PT_GNU_STACK 改变课程固定栈权限。其余程序头的允许忽略清单随工具链冻结，清单外类型明确拒绝。
- Section Header Table、符号表和调试信息不参与装载，可以不存在；无关节信息不得影响正常装载。
- 装载失败不能留下可调度的半成品任务，必须清理本次资源。
- 装载或重新装载用户代码后，在本 hart 执行这些代码前保证写入内容对取指可见；本课单核路线使用 fence.i 完成指令同步。该要求与页表变更后的 sfence.vma 分别处理，不引入多核远程指令同步。

### 任务 7.1：用户堆与用户缓冲区检查    【我们把基础用户内存接口收敛到 brk，用户库提供 sbrk 包装；基础采用立即分配，mmap/munmap 和缺页恢复移到选做。】

- 前置条件为最小用户 ELF 已能运行，使用学生自己的陷阱、地址空间和装载代码。

- 不依赖文件系统或用户堆，测试使用装载时建立的固定内存；用户堆组合测试另外列出依赖。

#### 测试覆盖哪些方面

- 轮转顺序、让出、到期唤醒、睡眠期间不运行、idle 后恢复。
- 设置一个在计算循环中不执行任何系统调用的用户任务，验证计时器能够中断其执行，使另一个任务在该计算任务完成前获得运行机会，并检查计算任务恢复后的结果和寄存器状态。不能仅凭两个程序最终都有输出判定抢占通过。
- 寄存器、栈和地址空间不串扰，退出任务不再次入队。
- 使用嵌入用户 ELF 验证一个任务等待控制台输入时，另一个就绪任务仍能推进；宿主随后注入字节，等待任务能取得输入并继续。该测试不依赖 shell 或文件后端。
- 未支持 trap cause 的行为与学生公开策略一致；若选择任务级终止，则进一步检查其他任务继续、资源清理和再次创建任务。

#### 结束条件

- 完成我们提供的用户程序的测试。
- 此阶段可由测试启动清单创建多个任务；shell 根据文件名动态启动在后续接入。

### 任务 7.3：共享式多接收者消息队列    【我们保留消息队列作为唯一 IPC，但不再使用每任务单接收者邮箱；改为具有独立队列 ID 的共享有界 FIFO，支持多发送者和多接收者，每条消息恰好由一个接收者取走。】

#### 想要让学生掌握什么

- 理解固定记录、消息复制、队列容量和普通消息 FIFO。
- 理解多个接收者竞争同一队列时，每条消息只被消费一次；队列为空时接收者阻塞，发送后唤醒其中一个等待者。
- 理解共享队列对象、队列 ID、显式删除、失效标识和任务退出清理，并区分普通消息与内核生成的完成事件。

#### spec 要说明什么

- 内核维护数量有上限的共享队列表；每个队列具有固定消息容量和固定记录大小，允许使用固定数组或环形缓冲区实现，不要求扩容。队列不是某个任务的收件箱，任何取得有效队列 ID 的任务都可以发送或接收。
- 提供课程调用 `mq_create()`、`mq_send(queue_id, message)`、`mq_recv(queue_id, message)` 和 `mq_destroy(queue_id)`；名称与原型为示意，调用号、参数布局、返回值和错误码由课程 ABI 表固定。队列 ID 是不透明标识，通过启动参数或已有通信交给其他任务，不要求队列枚举、按名称查找或每任务描述符表。
- 创建者是队列所有者并负责显式删除。所有者退出时，内核删除其尚未删除的队列；删除使队列 ID 失效、丢弃未读消息，并唤醒所有阻塞接收者返回“队列已删除”错误。队列 ID 的复用不得让旧 ID 命中新对象，允许使用索引加代次实现。
- 发送不阻塞：队列有空间时复制整条消息并返回，队列满则明确报错，不建立发送等待队列。接收有消息时取出完整记录，无消息时把当前任务登记到该队列的接收等待集合并阻塞；后续发送至少唤醒一个等待者。
- 普通消息按成功入队顺序 FIFO 出队，每条消息恰好由一个接收者消费。多个接收者并发等待或竞争时，不规定某条消息必须由哪个任务取得；测试检查整体无丢失、无重复和有限消息序列下的正常推进，不依赖特定调度顺序。
- 检查队列状态、登记等待者和交出 CPU 必须构成不会丢失唤醒的临界过程。任务因其他原因退出时，内核将其从接收等待集合移除；删除队列时全部等待者都必须被唤醒，不能永久残留阻塞任务。
- 消息记录包含固定大小用户载荷，以及由内核填写的来源任务 ID 和记录种类。用户发送只能产生普通记录，不能伪造内核生成的任务完成事件；这里的记录种类不是供用户筛选接收顺序的 SysV 消息类型。缓冲须覆盖完整记录；无效队列、坏用户指针、队列已满或已删除时按 spec 返回错误。失败发送不入队，失败接收不消费消息；不支持截断或部分消费。
- 基础范围不实现消息优先级、按类型选择、可变长度、阻塞发送、超时收发、通知回调、命名队列、权限控制、跨启动持久化或完整 SysV/POSIX 控制命令。这些未支持能力不得通过未说明的标志隐式接受。
- shell 创建一个不与普通 IPC 混用的完成队列，并在 spawn 时将其队列 ID 交给内核。spawn 只接受由调用者创建、当前为空且未绑定其他前台任务的队列；关联期间拒绝用户向该队列发送普通消息，因而至少保留一个位置用于完成事件。每个 shell 最多关联一个尚未领取完成通知的前台子任务；子任务正常退出时，内核向该队列恰好发送一次完成事件，选择任务级 trap 终止策略时使用同一流程。事件包含任务 ID、结束原因及退出状态，不依赖子任务主动发送。
- spawn 成功后内核在完成关联期间持有队列对象引用，避免对象存储被提前回收。所有者显式删除完成队列或退出时取消关联，子任务可以继续运行；已删除队列不再接收完成事件。正常路径中 shell 按普通 `mq_recv` 规则阻塞接收，子任务先退出后接收也不丢失通知；收到事件后释放前台关联，队列恢复为普通共享队列。

#### 实验指导书要编写什么

- 从创建一个队列并自发自收开始，解释固定记录复制和环形缓冲区；内部结构不限。
- 先演示多个发送任务向一个队列发送，再让多个接收任务在同一队列上阻塞和竞争，观察每条消息只被一个接收者取得。
- 讲清检查队列、登记等待和交出 CPU 的衔接，避免丢失唤醒；不在持有不能跨调度的锁时调度，不要求任意内核位置抢占。
- 演示队列满时发送立即报错、删除队列后唤醒全部接收者、所有者退出清理和带代次 ID 防止误用旧对象。
- 用 shell 专用完成队列演示内核生成事件、前台等待、对象引用和通知取消；不要求用消息队列进一步实现信号量。

#### 测试方式与前置条件

- 前置条件为任务 5 的用户缓冲检查、任务 6 的最小 ELF 和任务 7.2 的调度。使用固定缓冲，不依赖 brk、文件系统或 shell。
- 通过嵌入 ELF 和启动清单创建任务，将同一个队列 ID 传给多个发送者和接收者，并设置受控前台关联测试完成事件。按文件名 spawn 和 shell 等待在任务 8 验收，两阶段复用学生的内部创建逻辑。
- 测试使用学生自己的队列对象、任务状态、调度器和用户复制，不提供替代消息队列或阻塞框架。

#### 测试覆盖哪些方面

- 自发自收、多发送者向同一队列发送、普通消息 FIFO、记录内容与来源标识。
- 至少两个接收者在同一空队列上阻塞；连续发送多条消息后，各消息合计恰好接收一次，接收任务均能正常推进，不要求固定的消息到接收者映射。
- 队列满时发送立即报错且已有消息不变；坏缓冲和失败接收不消费消息。
- 无效、已删除或旧代次队列 ID 均不能访问其他对象；删除及所有者退出能够唤醒全部等待者并回收队列。
- 专用完成队列中的事件不会重复或被用户伪造；接收失败不提前解除关联，shell 退出时正确取消通知，子任务仍能正常回收。

#### 结束条件

- 多个任务能够通过共享队列完成多发送者、多接收者通信；每条消息只被消费一次，阻塞、唤醒、删除和退出清理正确，发送不因队列满而阻塞，且不遗留不可回收资源。

### 任务 7.4：最简文件系统的设计与实现    【我们删除 VFS 和现成文件系统后端，改为让学生依据公开格式实现一个扁平、固定容量的自定义文件系统；我们同时维护制镜像工具和参考内核实现，并用该文件系统真实存放课程所需程序和数据。】

#### 想要让学生掌握什么

- 理解文件系统如何在连续字节区域中区分元数据和文件内容。
- 理解名称查找、固定容量分配、文件长度和删除复用的基本设计。
- 在链接进内核的 ramdisk img 上实现创建、删除、整文件读取和整文件覆盖写入，并通过课程系统调用提供给用户程序。

#### spec 要说明什么

- 文件系统头的魔数、版本、镜像大小、文件项数量、单文件容量、名称长度、文件项大小、各区域偏移、字段宽度、字节序和对齐；无效镜像必须被拒绝，不能越界访问 ramdisk。多字节字段采用小端编码，保留字段必须按 spec 初始化和校验。
- 固定文件项包含有效标记、名称长度、当前长度和名称，每项数据槽位置按 `data_offset + index * slot_size` 计算。文件名采用 spec 限定的 ASCII 字符集合，是有长度上限的单个名称，不支持路径分隔符、NUL、目录、`.` 或 `..` 语义。
- `file_create(name)` 创建长度为零的新文件，并选择编号最小的空闲文件项；重名和文件项耗尽时报错。
- `file_delete(name)` 删除已有文件并释放文件项；文件不存在时报错。删除不要求擦除整个数据槽，但旧内容不可通过接口读取，重新使用该项时初始文件仍为空。
- `file_read(name, buffer, capacity)` 只在缓冲区足以容纳完整文件时复制，并返回实际长度；缓冲不足时返回错误且不进行部分复制。
- `file_write(name, buffer, length)` 只写入已经存在的文件，用输入内容原子地替换整个文件；文件不存在、长度超过固定容量或复制用户数据失败时保持原文件不变。这里的“原子”只指一次系统调用成功或不产生可观察的修改，不要求崩溃一致性。
- 名称格式、空名称、最大长度、坏用户指针、镜像损坏、容量耗尽和整数溢出的错误返回。接口名称为设计示意，最终调用号和结构体以 ABI 总表为准。
- 内核内部按名称取得文件数据起点和长度的接口及其生命周期。ELF 装载器可以直接解析固定数据槽中的连续字节并将段复制到用户页，但不能跨文件修改保留该视图；该接口不向用户态公开，也不引入打开文件对象。
- 不提供目录、枚举、打开/关闭、fd、偏移、追加、局部读写、截断、权限、链接、挂载、多个后端、VFS、日志和断电恢复。

#### 实验指导书要编写什么

- 画出文件系统头、文件项表、对齐填充和固定数据槽的布局，用一个文件手算对应项和 `data_offset + index * slot_size` 数据范围。
- 说明跨宿主工具、C 和 Rust 共享磁盘格式时为何不能依赖本机结构体填充，演示按固定偏移读写小端字段。
- 从校验魔数和边界开始，实现名称比较与查找，再依次实现创建、整文件写入、读取和删除复用。
- 说明先完整校验名称、长度和用户缓冲区，再写入固定数据槽，最后提交文件长度；在本课单线程用户任务、内核态不抢占的模型下，校验完成后用户映射不会在本次调用中变化，因此不要求为整个文件另设一份内核暂存副本。
- 解释固定数据槽用空间换取实现简单：无需空闲块分配和碎片整理，但文件数和单文件大小受限。
- 说明 ramdisk 修改直接发生在链接范围内；独立测试通过重启 QEMU、重新加载原始镜像恢复干净状态。
- 使用显式文件清单和镜像制作工具生成包含 shell、编辑器、cat、rm 及必要数据的初始镜像，再用检查工具查看同一文件系统的宿主侧表示。说明这些工具只用于准备和检查镜像，不能替代学生内核中的实现。
- 跟踪参考内核从名称查找取得连续文件范围、校验 ELF 并复制 `PT_LOAD` 段的过程，说明文件系统只改变字节来源，不替代 ELF 校验与地址空间构建。

#### 测试方式与前置条件

- 前置条件为最小用户 ELF 已能运行。基本文件测试使用固定缓冲区，不依赖调度和完整用户堆。
- 我们提供格式说明、原始 ramdisk img、预置文件清单、链接段、边界符号、镜像制作和检查工具；学生实现镜像校验、元数据操作、数据复制、内核名称查找接口和四个课程系统调用。
- 每个独立测试恢复干净镜像，避免前一用例影响后一用例。
- 用户程序经过学生系统调用检查文件行为。基础文件系统测试不要求并发访问；允许内核态不被计时器抢占的课程模型保证一次文件操作完成后再进入下一次内核操作。

#### 测试覆盖哪些方面

- 宿主侧工具生成的空镜像和预置镜像均能由参考内核及学生实现初始化；魔数、版本、范围或长度损坏时安全拒绝。
- 创建、重名、确定性选择编号最小的空闲项、文件项耗尽、删除、删除后复用，以及其他文件不被破坏。
- 空文件、整文件写入与读取、覆盖为更短或更长内容、最大容量和超过容量。
- 缓冲不足、非法名称、坏用户指针和整数溢出失败时不产生部分修改。
- 用户 ELF 与普通数据都通过学生实现的同一文件系统读取；ELF 装载可以直接使用名称查找返回的连续字节范围，但不通过测试脚本绕过文件系统直接查找嵌入地址。

#### 结束条件

- 完成四个文件操作测试，并能按名称从最简文件系统读取用户 ELF 的完整字节。

### 任务 8：从 shell 按文件名启动程序并通过消息队列等待完成    【我们取消 fork、waitpid 和僵尸进程，由 shell 创建专用共享队列等待前台完成；程序通过最简文件系统的扁平名称读取，退出通知由内核生成并在安全切换后回收资源。】

#### 想要让学生掌握什么

- 将文件、ELF、地址空间和任务管理组合为程序启动过程。
- 理解命令行参数、完成事件和前台输入归属。
- 在失败后恢复可用状态。

#### spec 要说明什么

- 按扁平文件名创建并装载任务的最小接口，不需要路径解析或 fork。
- shell 创建专用完成队列，spawn 接收该队列 ID 并返回新任务 ID；队列必须由调用者创建、当前为空且未绑定其他前台任务。每个创建者最多一个未领取完成事件的前台关联，关联期间普通发送被拒绝。正常 exit 由内核向该队列投递完成事件；任务级 trap 终止采用同一流程，创建者删除队列或退出后取消通知。
- shell 通过 `mq_recv` 在专用队列上阻塞等待，不提供通用 waitpid、父子进程等待或 POSIX 僵尸进程语义。当前任务退出后先离开运行态，内核切换到其他栈后再回收其内核栈和地址空间。
- 参数长度和数量限制，以及启动失败时原 shell 不受破坏。
- stdin/stdout/stderr 的初始约定，前台期间谁可以读取输入。
- shell 恢复后仍能连续启动下一程序；后台、管道和重定向不要求。

#### 实验指导书要编写什么

- 跟踪一次 shell 请求从最简文件系统名称查找、整文件读取、ELF 校验、装载到加入就绪队列的过程，复用基础阶段的装载逻辑。
- 展示参数字符串和指针在用户栈中的布局，解释对齐、终止标记、长度限制与用户地址转换，再接入多个参数测试。
- 解释 shell 如何阻塞接收完成消息，内核如何在正常 `exit` 路径中可靠投递事件并唤醒 shell；任务级 trap 终止是学生选择该策略后的扩展路径。
- 提供应用源码阅读路线，不让学生承担 shell 语法解析和编辑器移植。
- 演示正常退出、不存在的文件名、坏 ELF 和失败回滚；根据学生公开的未支持 cause 策略，另行观察用户 trap 导致的任务终止、panic 或关机。
- 说明前台运行时暂停 shell 读取输入的最小方法，不引入完整终端作业控制。

#### 测试方式与前置条件

- 前置条件为学生最小用户环境、任务调度、消息队列和最简文件系统完成。参数打包使用已有页管理；若用户库需要动态分配，则先完成 `brk/sbrk`。
- 使用提供的 shell 与用户程序，通过 UART 注入命令并检查结果，全部经过学生内核实现。
- shell 和命令程序从最简文件系统按名称读取，嵌入测试 ELF 只保留为早期测试产物。

#### 测试覆盖哪些方面

- 带多个参数启动程序，参数内容正确。
- 前台运行期间 shell 不抢走输入，退出后可以继续操作。
- 通过真实的按文件名 spawn 验证新任务 ID、专用完成队列 ID、已有前台关联时拒绝再次启动、创建失败回滚、子任务提前退出后仍能收到通知，以及 shell 在领取完成事件后继续启动；复用任务 7.3 的共享队列和内部创建逻辑。
- 文件不存在、坏 ELF 和内存不足后 shell 仍可用。只有采用任务级 trap 终止策略时，才要求相应用户异常后 shell 继续可用。
- 连续启动、完成消息接收和正常退出没有资源泄漏；采用任务级 trap 终止策略时，故障任务不依赖主动发送消息也能通知 shell。
- cat、rm 确实作为 ELF 被启动，不由 shell 偷换成内置实现。

#### 结束条件

- 结束条件为可以在 shell 中连续启动不同程序，并从启动失败中恢复；未支持 trap cause 按公开策略验收。

### 任务 9：综合场景与资源回收

#### 想要让学生掌握什么

- 根据跨模块现象定位边界错误，解释完整用户请求的执行路径。
- 确认多次运行后的状态和资源仍然正确。

#### spec 要说明什么

- 基础演示的准确步骤、必要输入和结果。
- 创建新文件、修改已有文件、检查内容和删除均要覆盖。
- 多任务并发与用户隔离单独验收，不能由编辑器演示替代。
- 测试结果必须完整，失败、崩溃和超时不能算通过。

#### 实验指导书要编写什么

- 给出完整命令序列和预期文件结果。
- 说明模块单测通过、集成失败时应检查参数、内存复制、资源所有权和清理顺序。
- 指导学生缩小复现用例，保留有效日志，不要求长篇重复记录开发过程。

#### 测试方式与前置条件

- 用户程序与宿主 UART 脚本联合测试，使用完整学生内核。
- 基础部分的综合验收由助教查看演示过程确认结果。

#### 测试覆盖哪些方面

- 完整 shell、编辑器、cat、rm 流程及文件内容，覆盖创建、整文件覆盖写入、读取和删除。
- 重复执行、失败后再次操作、并发运行和正常退出后的资源回收；采用任务级 trap 终止策略时，再检查相应异常退出后的资源回收。
- 全部 case 有结果和结束记录，不能出现未完成测试却输出总通过。

### 任务 10：图形、输入与 mGBA

#### 想要让学生掌握什么

- 将已有驱动接入自己的内核，管理设备与用户程序之间的数据传递。
- 理解帧缓冲、输入事件及实际应用对内核服务的使用。
- 理解 DMA 缓冲的物理地址、对齐、所有权与设备使用期间的生命周期。

#### spec 要说明什么

- 驱动要求的分配、映射、中断回调及外部 ABI。
- 帧格式、缓冲长度、提交后是否继续借用用户内存、输入事件顺序与队列边界。
- mGBA 使用的已公开系统服务及附加验收范围。
- 不把应用移植、音频、重启后存档和固定帧率作为学生要求。
- 学生按我们提供的驱动的公开要求，将已有页管理接入 DMA alloc/dealloc 回调；我们负责驱动实现、C/Rust 接口适配和调用示例。连续性、对齐、地址转换、释放时机及所需同步操作提前写入契约，不引入通用 IOMMU 或完整 DMA 子系统。

#### 实验指导书要编写什么

- C/Rust 分别如何接入驱动，如何提供所需回调。
- 从纯色或棋盘格显示、按键事件打印，到运行 mGBA 的步骤。
- 如何区别通道顺序错误、事件丢失、用户缓冲错误和应用适配问题。
- 明确应用侧代码由我们负责，不要求学生改造 mGBA 核心。

#### 测试方式与前置条件

- 前置条件为基础内核完成。可在学生内核中用简单的内存显示记录和事件注入检查接口，不替代地址空间、陷阱和调度。
- 用户程序检查帧传递与输入，再使用提供的驱动和 mGBA 验收。

#### 测试覆盖哪些方面

- 帧尺寸、颜色和缓冲区边界，返回后修改原缓冲不会造成未约定的异步访问。
- 按下和释放、事件顺序、空队列、队列溢出后的恢复。
- mGBA 能加载 ROM、产生画面并响应实际操作。

### 明确不纳入本版的范围

目录、路径、文件枚举、fd 文件接口、工作目录、重定向、管道、后台任务、shell 脚本以及 `if`、`for`、变量展开和命令替换均不纳入 v0.0.3，不编写必过测试，也不计入基础预算。后续版本若扩展这些能力，需要重新评估文件系统格式、系统调用、应用适配和学生工作量。

## 自主推进与阶段检查

### 学生如何推进

课程实验采用持续、自主推进方式。指导书按模块和依赖提供完整学习路线，学生自行安排投入，不要求所有人在同一天完成同一模块。

指导书应覆盖从干净环境到综合验收的全过程。每个模块给出前置条件、必要知识、实现步骤、可观察结果、测试方法和常见错误，使学生能够据此开始并持续推进。文档或示例暴露出共性缺漏时及时补充，不能把必要内容留到口头答疑时才讲。

学生遇到问题可以随时联系助教，不设置专门的答疑日，也不要求等到阶段检查再求助。指导书说明如何整理复现步骤、相关代码、日志和已经尝试的方法，便于助教定位问题。答疑、调试和修改贯穿整个实验过程。

### 建议路线与阶段成果

| 阶段 | 建议工作 | 可以检查的成果 |
| --- | --- | --- |
| 工程与输入输出 | 运行工程、外部符号练习、UART | 能进入学生内核、调用外部函数、取得链接边界并完成串口输入输出 |
| 公共基础 | 人类可读机器规范与 MMIO、陷阱、物理页、Sv39 用户地址空间、最小 ELF 装载 | 单个用户 ELF 在独立地址空间中调用系统调用并退出 |
| 核心模块扩展 | 用户堆、等时间片 RR、消息队列、最简文件系统，按依赖选择先后顺序 | 在自己的内核上运行各模块测试，满足条件后补充组合测试 |
| 应用与综合验证 | shell、命令程序、编辑器及完整内核联调 | 从最简文件系统按名称启动程序，完成文件创建、覆盖写入、读取和删除 |
| 提交与验收 | 整理代码、测试结果和设计说明，完成验收 | 能复现测试结果并解释自己的实现与取舍 |

这张表表示建议顺序，各模块仍估算阅读加编码时间，具体估算经参考实现和学生试做核对后写入指导书，供学生安排进度。阅读加编码总预算暂以 48 小时为可行性目标；环境、调试和集成另外记录，并用于判断整体设计是否过量，而不设置统一的每日进度或固定答疑日。

机器规范与 MMIO、外部符号及高半启动原理计入公共基础预算，最简文件系统的格式理解和四个操作计入核心模块预算，消息队列单独计入核心模块预算。试做超出预算时，按已确定的原则调整任务或支持范围，不能要求学生用全部空余时间填补设计超量。

任务 0 至任务 6 构成公共基础，按列出的依赖逐步完成。后续用户堆、调度和文件系统测试共同依赖任务 6；消息队列依赖任务 5 的用户缓冲区检查、任务 6 和任务 7.2，不依赖 brk。用户堆、IPC、文件系统与退出清理的组合测试需要相关模块同时完成。shell 接入依赖任务调度、消息队列和最简文件系统，综合验收依赖全部基础功能。

### 阶段检查如何进行

阶段检查随学生完成进度进行，重点观察工程与 UART、最小用户运行环境、核心模块和综合场景这些成果，不绑定固定日历日。学生完成一个阶段即可运行公开测试、检查结果并提交阶段成果；尚未完成时也可以带着当前代码和问题寻求帮助。

检查用于发现前置功能缺失、理解偏差和集成问题，不承担首次讲授必要知识的职责，也不限制学生继续学习。需要补测时，修正后再次运行对应测试即可。正式阶段提交要求和分值由负责人确认。

学生达到验收条件即可申请验收。附加题按所需能力和个人进度安排，不占用基础部分的必做时间预算。

## 验收与评分

- 本版按测试点累计得分，允许明确的阶段依赖，具体权重待讨论确认。
- 测试及源码全部公开，不设置隐藏测试。
- 自动测试抓取 UART 结构化记录，检查用例身份、状态和结束标记，区分失败、未实现、崩溃和超时。
- 启动、UART、陷阱、首次运行用户 ELF 分别保留可验收成果；公共基础尚未完成的学生仍可获得已通过阶段的成绩。
- 后续用户测试需要先完成公共基础，不保证任意模块在空内核上获得成绩。因前置条件不足而未运行的测试单独标记，不伪装成已执行的模块失败；具体计分由评分方案规定。
- 测试必须覆盖正常行为和公开边界；实现风格、目录结构和算法选择不作为隐含评分项。
- 学生可以使用 AI 工具，原则上说明使用情况。验收时可以询问代码和具体设计，不以 AI 检测结果判定成绩。
- 附加题允许补偿基础分，具体加分和封顶规则待评分方案确定。
- 参考内核先用于内部验证，是否公开另定。

按照我们的原则，优先保证认真实现的学生可以理解和完成验收，并通过代码和设计交流了解学习情况。我们不设计严格的反作弊和反 AI 工具，仅严格拒绝硬编码输出信息欺骗测试脚本的情况。

“通过测试”表示满足当前验收覆盖的约定，不表示任意程序都能运行。

## 课程准备工作与建设计划

### 最终交付内容

- 本设计方案：说明原则、范围、分工、模块和建设安排。
- spec：给出外部接口、行为、错误、资源边界和验收要求。
- 实验指导书：提供自主完成实验所需的完整学习资料，按模块和依赖组织，给出投入时间估算；公共基础逐步引导，后续模块列明依赖和测试方法，并覆盖排错与综合验收。
- C/Rust 工程框架：提供物理入口、高半链接、boot 页表、构建、工具配置和运行调试脚本；包含外部函数调用、学生接口导出和链接边界取址的教学示例。
- 标准 VMware 虚拟机：固定 Ubuntu、QEMU、OpenSBI、编译器、GDB、依赖和课程资源，并提供镜像校验、导入说明及我们使用的重建脚本。
- 固定 QEMU 机器资料：完整启动命令、人类可读机器规范和 C/Rust 平台常量，直接列出 RAM、必要 MMIO 设备和计时属性；学生材料不包含平台描述二进制、源码或解析器。
- C/Rust SBI 调用适配与示例：SRST 关机、TIME 计时器、BASE 环境检查，配套固件配置及关机判定脚本。
- 可用的固定容量内核堆：链接预留区、初始化、C 分配释放接口、Rust 全局分配器、同步与耗尽处理，以及使用讲义。
- 直接使用高半符号的链接器脚本、物理入口、临时栈、完整 boot 页表、激活页表的入口汇编和链接产物检查脚本；boot 页表包含高半内核及规定的低地址 MMIO 恒等映射，学生仍负责通用 Sv39 页表和用户地址空间设计。
- Rust 参考内核：验证全部必做要求，包含实际读取和修改课程最简文件系统的参考实现；分别统计学生核心代码、我们提供的框架和驱动支持代码。
- 少量早期内核探针、测试源码、必要对象文件、用户 ELF 和判分脚本，不提供替代核心模块的运行外壳。
- 课程自定义最简文件系统的完整格式规范、预置文件清单和 ramdisk img、宿主侧镜像制作/检查/查看工具、参考内核实现、可写 loadable 链接段、虚拟和物理边界符号及 C/Rust 字段访问示例；学生实现镜像校验、名称查找以及创建、删除、整文件读取和整文件覆盖写入。文件项数量和单文件容量在完成必需用户程序的真实构建、裁剪和容量统计后写入 spec，基础规格不由选做 ROM 等大文件决定。
- 嵌入资源的符号与偏移清单、C/Rust 常量及调用示例：统一使用 ramdisk_start、testcase_api_start、testcase_elf_start 加字节偏移定位资源，并随最终链接产物生成或校验长度、签名和范围。
- 共享消息队列 ABI、用户库、测试程序和 shell 完成事件协议：独立队列 ID、固定记录与容量、多发送者、多接收者、非阻塞发送、阻塞接收、显式删除和退出清理；不要求消息优先级、超时、完整 SysV/POSIX 控制接口、信号量、waitpid 或管道任务。
- shell、简化编辑器、cat、rm 及用户库，按本版 Linux RISC-V 64 位裁剪 ABI、课程文件调用和共享消息队列调用完成适配。
- 完整 Virtio-GPU/Input 驱动接入包与移植后的 mGBA。
- 验收说明、常见问题、参考运行记录和试做修订记录。
- 一份具体的实验要求，包括要完成哪些任务，以及交付哪些实验报告。

注：参考内核使用 Rust 不等于我们只验证 Rust。我们还需要用 C 工程实际验证各测试钩子、结构体布局、预编译对象和驱动接入，保证 C 学生不需要迁移到 Rust 才能完成。
