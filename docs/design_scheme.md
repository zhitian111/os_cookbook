# 设计方案

## 文档定位

- 说明这次课程实验要做成什么样子
- 说明学生需要完成的工作，以及我们提供的代码、工具和教学材料
- 记录设计原则、功能边界和已经做出的取舍
- 列出课程准备工作和最终交付产物
- 尚未确定的问题单独列出，后续通过参考实现和试做调整

## 学生基础与实验约束

- 认为所有人都只是学习过操作系统的概念性知识，无任何操作系统开发相关的经验或知识
- 认为所有人都能力边界都符合如下几条约束：

### 可以假定学生掌握的内容

- 已经学习过操作系统课程，了解进程、内存、文件和用户态、内核态等基本概念。
- 会编写 C 语言程序。
- 能按照指导修改代码、复制命令、运行程序和查看输出。

### 不能假定学生掌握的内容

- Linux 终端、Git、Makefile 和交叉编译工具链。
- QEMU、GDB、readelf、objdump、nm 等工具。
- 入口汇编、链接器脚本、可执行文件的加载和内存布局。
- RISC-V 指令、CSR、陷阱入口和特权级切换的具体实现。
- 编码智能体；教学支持不能依赖学生会使用 Codex、Claude Code 或 Cursor。

## 设计原则

### 可完成性约束

- 必须让符合上文描述能力边界的学生可以完成除附加题以外的实验
- 预期工作量都必须只考虑古法编程的情况（即不借助任何 AI 工具进行编码工作），要让纯手写的人可以无压力的完成实验

### 学生主要实现操作系统功能

- 不能让学生需要去学习与操作系统内核无关的，仅会用到一次的知识
- 不让一次性的工程配置占用主要实验时间。
- 必须接触的底层知识由指导书解释，不要求学生自行查齐所有资料。
- 提供启动、构建、调试和测试所需的代码，不提供需要学生实现的内核功能
- 不指定学生的内核目录结构、内部数据结构和具体算法，除非测试兼容性确实需要。
- 所有测试程序，只定义要被验收的接口格式和语义，不定义内核的结构

### 每个模块都能独立开始

- （当跟随实验指导书完成前置实验后）学生不需要先完成其他模块，就能开发和测试当前模块。
- 模块独立验收，完整内核另做集成验收。
- 教学讲解可以按顺序展开，不把讲解顺序变成学生必须遵守的开发顺序。
- 尽可能保证任务的独立性和可并行性，只在必要的时候做线性的任务安排

### 要求必须能够被测试

- 每项必做功能都提供容易运行的测试。
- 测试只检查 API/ABI 的行为，不检查学生是否采用指定内部实现。
- 同时测试正常行为、边界输入和失败后的状态。
- 不用未公开的功能要求扣分。
- 测试失败应帮助学生定位问题，不能只输出一个 FAIL。

### 时间与工作量

- 按两周安排，给阅读、调试和其他课程留出时间。
- 按单个学生独立完成设计，不依赖多人分工。
- 学生实现代码预计约 3000 至 4000 行。
- 实际编码时间预计不超过 48 小时，另外估算阅读、调试和集成时间。
- 行数和时间先作为预算，通过参考实现和试做验证，不作为评分指标。

### 评价不能增加无关负担

- 所有评分标准都不能惩罚认真做事的学生，哪怕会漏掉直接完全通过 AI 工具完成实验或者抄袭别人的代码的学生
- 集成单独评价。
- 不以代码行数、实现速度或 AI 检测结果判断成绩。
- 不阻止学生使用 AI 工具。
- 不为防止少数学生完全依赖 AI，给认真完成实验的学生增加大量额外工作。

## 一些重要问题的决定

### 定义“从零开始”

一句话：学生在可启动、可调试的工程中，自行设计并实现操作系统核心功能。

具体而言，学生在可启动、可调试的工程中，自行设计并实现操作系统核心功能。

我们提供入口汇编、链接器脚本、Makefile、工具链配置以及启动 QEMU、连接 GDB、嵌入资源和运行测试的脚本。学生可以直接进入自己的 C 或 Rust 内核入口，不需要先解决固件交接和构建布局。

UART、陷阱入口、上下文切换、最小 ELF 解析和被验收的核心模块由学生实现。指导书可以给出 printf、println、CSR 和 SBI 的参考用法，但 spec 不规定学生必须采用这些封装。

参考内核使用 Rust，先用于内部验证课程可行性。是否向学生开放后续再决定，不能把参考实现默认视为学生工程的一部分。

### 关于驱动程序的实现边界

考虑到大部分驱动程序其实都有现成的轮子，且实际的开发场景中内核侧的工作主要是适配驱动而不是实现驱动，对于设备相关的任务只要求学生了解 dtb，以及通过简单的 uart 驱动了解驱动开发的工作内容即可，对于其他需要的设备驱动，由我们提供实现或者第三方依赖库。

### 关于文件系统的实现边界

考虑到实际实现一个可以增删查改，支持多级目录，支持大文件，支持符号链接等的文件系统这件事本身是一个很麻烦的工作，尤其对于从零开始的学生来说，因此暂定使用简单的只读 ramdisk + eazyfs 的形式，由我们提供适配层或第三方依赖库。ramdisk 不做分区，物理块号和逻辑块号一致，第一个块就是文件系统的 super block

### 关于内存的实现边界

只要求 SV39 4K 页分配实现，不要求懒分配，COW 等复杂机制

关于内核页表，学生可自行决定是将内核与用户地址空间写入同一页表还是分别写入两个不同页表，因此也不指定学生是否需要将内核符号放在高位地址

### 关于实现质量的要求

只要求功能的可用性，不要求性能

### 关于测试程序运行环境的假设

所有测试程序均认为运行在单核且可并发的环境内，但测试程序均为单指令流（线程）程序

### 自定义 ABI 设计方式

对于 Linux ABI 包含的语义，使用与 Linux 相同的系统调用号和参数列表，但是不要求复杂功能，将非必要功能裁剪或要求固定其中部分参数

对于 Linux ABI 不包含的语义，使用 1024 + n 定义系统调用号

## 课设目标

### 学生需要完成的基础任务

- 在提供的工程框架中实现一个单核 RISC-V 内核，支持 Sv39 虚拟内存和独立用户地址空间。
- 实现 UART 输入输出、陷阱处理、用户态与内核态切换、内存管理、ELF 校验与装载、任务管理和 VFS。
- 实现时间片抢占、主动让出、睡眠和退出。指导书默认讲解 round-robin 调度。
- 实现约定的自定义系统调用，不要求兼容 Linux ABI。
- 先完成最小用户程序运行环境，后续模块主要在学生自己的内核中通过用户程序测试。
- 能同时运行多个用户程序。使用不主动让出的计算程序、周期输出程序和睡眠程序检查调度与隔离，不能只用前台程序顺序执行代替并发验收。
- 当前基础综合场景为：内核启动后进入 shell，根据路径启动文本编辑器，创建或修改文件并保存，编辑器退出后返回 shell，再运行 ls、cat、rm 检查文件、读取内容并删除文件。该场景是否扩展，视工作量而定。
- shell、编辑器、ls、cat、rm 由我们提供和适配。ls、cat、rm 作为可执行文件存在，不作为 shell 内置命令。
- 所有程序和数据通过统一根文件系统访问，文件修改只要求在本次运行期间有效。

### 学生需要完成的附加任务

- 接入我们提供的完整 Virtio-GPU 和 Virtio-Input 驱动，完成内核中的接口与资源管理。
- 运行我们移植的 mGBA，加载指定 ROM，显示画面并响应操作。
- 不要求声音、QEMU 重启后的存档恢复和固定帧率，运行期间能够正常操作即可。
- mGBA 移植、宿主依赖裁剪和应用侧适配由我们完成，不作为学生任务。
- 附加部分单独提供测试和指导，不能阻止基础部分验收。

### 想要达到的教学目标

- 理解内核程序的运行条件，能够使用提供的工程和调试工具开始内核开发。
- 理解设备寄存器访问，完成最小 UART 驱动。
- 理解陷阱现场保存、系统调用入口、特权级转换和执行流恢复。
- 理解物理内存、虚拟地址和用户隔离，设计自己的内存管理方式。
- 理解 ELF 文件如何变成一个可执行的用户任务。
- 理解任务状态、时间片、阻塞和唤醒，实现多个用户程序的并发运行。
- 理解文件节点、打开状态、文件描述符和任务资源之间的关系。
- 能根据公开测试、日志和调试信息定位错误，并解释自己的设计。

## 总体设计思路

### 从用户程序的需求确定必做功能

先确定基础用户程序和运行场景，再分析它们需要的最小内核服务。每项内核服务都要对应教学目标或基础程序的实际需求，不为了接近完整 Unix 而增加功能。

应用适配时优先裁剪与教学无关的需求。不能因为选中的编辑器需要完整终端管理，就把相关机制全部变成学生任务。应用需要的内核行为必须进入 spec 和测试，不在最终演示时突然要求。

即当 spec 定下来后，所有的任务安排以及测试样例都需要围绕 spec ，spec 确定后就不再改变

### spec 与实验指导书分别写什么

spec 说明输入、输出、行为、错误、资源归属和验收边界。除外部兼容要求外，不规定源文件组织、私有结构体和具体算法。

指导书解释如何开始、为什么需要这些机制、如何实现一种容易理解的方案，以及如何检查错误。学生可以选择其他满足 spec 的实现。

例如，内存接口必须满足约定，但立即分配和懒分配由学生决定。指导书先讲一种最小实现，再说明另一种方案需要额外处理的情况。round-robin 作为默认教学算法，spec 则需要明确本课要求的轮转行为。

### 区分学习顺序与实现顺序

指导书按照学生建立内核的经历展开：运行工程、UART、陷阱、地址空间、最小 ELF 装载，随后扩展内存接口、调度、文件和 shell，最后综合验收。

前半部分是公共基础，按顺序引导学生完成单核、单用户任务、Sv39 地址空间、ELF 装载和最小系统调用。此时不要求调度器、完整 brk/mmap/munmap 或 VFS。指导书写清观察和排错步骤，不由我们提供的运行环境替代学生的核心模块。

公共基础通过后，内存接口、调度和 VFS 可以按依赖分别推进。每个测试列明需要哪些已完成能力，不为消除依赖而编写可替换的参考模块。学生可提前编写其他模块，但不承诺在基础未完成时就能验收它们。

第一个测试 ELF 直接链接进内核，通过起点和长度装载。学生使用自己的页分配器和页表建立代码、数据和固定用户栈，暂不依赖文件系统、用户动态内存或命令行参数。VFS 完成后更换文件来源，最终通过根文件系统读取程序；带参数启动和等待在 shell 阶段补齐。

### 控制额外工作量

驱动、磁盘文件系统后端和应用移植等部分过重时，由我们提供代码。核心模块过重时，减少必做范围，而不是要求学生在同样时间内完成更多功能。

计划按两周安排，阅读加编码预算不超过 48 小时，参考内核约 3000 至 4000 行。调试和集成时间另外记录，也必须纳入两周是否可完成的判断，不能把超时都归为不计预算的调试。

## 功能范围与师生分工

### 平台与语言

- 正式支持 C 和 Rust，学生任选一种，不要求同时学习两种语言。
- 统一支持虚拟机中的 Ubuntu 26.04.1 LTS，环境配置教程从干净的 Ubuntu 26.04.1 LTS 开始，完全使用阿里云中可以获取到的 APT 管理的软件包或 Github 开源项目搭建实验环境。
- 熟悉其他环境的学生可以自行配置，我们不承诺同等的环境排查支持。
- QEMU、固件、编译器及内存布局由我们统一验证和发布，学生不负责平台选型。
- C、Rust 与预编译测试遵循共同的外部 ABI；语言内部结构由学生决定。
- QEMU 启动命令统一提供
- 项目需要的所有构建和 QEMU 相关的命令都会封装进 Makefile 中

### 内存和任务

- 使用 Sv39，建立独立用户地址空间，禁止用户程序访问内核及其他任务的私有内存。
- 实现基本页管理以及 brk、mmap、munmap 对应的约定行为。具体调用名称与参数在 spec 中确定。
- 分配策略由学生决定。spec 必须兼容允许的策略，说明资源耗尽发生在申请阶段还是首次访问阶段时各自怎样处理。
- 实现时间片抢占、让出、睡眠和退出，默认教学采用 round-robin。
- 支持多个用户任务，不要求线程和完整进程信号机制。
- 信号量是候选扩展，不作为已确定的必做功能；并发验收不依赖它。

### shell 与用户程序

- shell 根据路径请求内核创建并装载用户任务，支持命令行参数。
- 基础方式为前台执行：shell 等待程序退出，随后继续接收命令。
- 程序启动失败或用户程序异常退出后，shell 应继续可用。
- 前台运行期间需要明确输入归属，避免 shell 和子程序同时读走串口输入；不要求完整终端作业控制。
- shell 的基本使用方式接近常见 sh，但不以完整 sh 兼容性验收。
- 不要求环境变量和管道。重定向、后台任务与脚本执行待工作量评估后决定。
- 编辑器允许简化。终端字节序列、编辑操作和屏幕刷新由我们在应用侧适配；学生只实现已公开的内核接口。

### 文件系统

- 我们提供块设备接口和文件系统后端，预计将文件系统镜像链接进内核，再在内存中操作。后端的选择暂时考虑使用 eazyfs。
- 学生负责 VFS，包括路径处理、文件描述符、打开偏移、访问模式、系统调用适配和退出清理。
- 后端提供节点级操作，不提前完成每任务文件描述符和打开偏移管理。
- 挂载、创建、读写、删除、目录枚举、截断和文件扩容属于当前必做文件操作；磁盘空间分配和格式维护可由后端完成。
- 用户 ELF 和数据文件通过同一根文件系统读取。但也考虑在学生刚实现 ELF 装载需要做测试的时候在完整内核中另设一套绕过 VFS 的程序名称到内存地址表。
- 多级目录、相对路径、chdir、getcwd 是否必做，视工作量而定。当前不为它们设必过测试。
- 学生是否进一步实现磁盘文件系统，视工作量决定。本文的基础预算按照提供后端估算。
- 不要求 Virtio-Block 和重启后持久化，也不要求磁盘故障恢复。

### 显示与输入

- 我们提供完整 Virtio-GPU/Input 驱动及 C、Rust 可用的接入方式。
- 学生负责将驱动接入自己的内核，并完成约定的用户显示和事件接口。
- 图形、输入和 mGBA 为附加部分，基础 shell 使用 UART。
- 驱动需要的分配、映射和中断回调必须提前列明，不能在附加题中隐含要求学生学习另一套完整内核框架。考虑使用阻塞式的实现而非中断式的实现。

## spec、实验指导书与测试的组织

### 每个模块都写清的内容

每个模块说明教学目标、spec 范围、指导书内容、前置阶段、测试方式、测试覆盖范围和预计工作量。不承诺每个模块都能从空内核独立开始。

内核符号测试调用约定的公开函数，不读取学生私有结构。涉及用户可见行为时，后续必须再经过真实用户态和系统调用验证。

早期测试提供源码和必要的对象文件；用户测试提供源码和 ELF。内核符号测试只用于容易直接检查的少量早期功能。需要固定入口或弱符号时由工程处理，弱默认实现只报告未实现，不提供目标功能。

不建设能替代学生内存、陷阱、装载和调度模块的测试外壳。启动栈与资源布局由工程骨架提供，其余运行能力由学生逐步完成。固定入口仍要求代码已加载、特权级和栈有效，不能绕过前置条件。

早期测试的链接与节回收由我们处理和检查。公共基础完成后，测试尽量只使用用户 ABI，减少强制导出的内核符号。C/Rust 遵循共同的外部约定。

以下工作量为初步预算，不是已经测出的结果。一个“投入日”按约 4 小时阅读加编码计算，0.5 天约为 2 小时；日历安排另外保留调试、答疑和集成时间。行数只估算学生实现，不含我们提供的基础设施、后端、应用和测试。

### 任务 0：运行工程与观察启动过程

#### 想要让学生掌握什么

- 能构建内核、启动 QEMU、连接 GDB 并查看输出。
- 知道入口汇编、链接脚本和内核主函数各自负责什么。
- 知道自己实际需要修改哪些文件，如何保存和恢复一次修改。

#### spec 要说明什么

- 支持的平台、语言、工具链与构建入口。
- 学生入口的调用约定，以及进入时已经建立的栈和内存条件。
- 内核、测试、镜像和保留区的布局约束。
- 固定测试入口的运行前提，哪些基础设施修改后仍须满足相同约定。

#### 实验指导书要编写什么

- 从干净 Ubuntu 26.04.1 LTS 安装工具、取得工程、构建和运行的完整步骤。
- C、Rust 分别给出最小操作路线，不要求学生阅读另一种语言的章节。
- 解释启动栈、BSS、链接地址和 ELF 加载段；给出入口断点与一次单步观察。
- 只教授本课需要的 Git、make、readelf、nm 和 GDB 命令，每条命令说明用途与正常结果。

#### 测试覆盖哪些方面

- 入口、栈和加载段符合约定，测试及镜像区域未被覆盖。

#### 结束条件

### 任务 1：UART 输入输出

#### 结束条件

### 任务 2：外部函数与链接符号的使用

这部分放在工程启动教学中，先用 GDB 观察，UART 完成后再打印结果。设备树与物理页模块直接复用这里的知识，不让学生第一次分配物理页时才接触 extern 和链接符号。

#### 想要让学生掌握什么

- 区分源文件中的声明、其他对象文件中的定义，以及链接器最终确定的符号地址。
- 能调用我们编译并链接进内核的测试函数，也能导出自己的接口供测试代码调用。
- 区分外部函数、真正存有数据的外部变量和仅表示位置的链接边界符号。

#### spec 要说明什么

- 外部测试函数统一使用 C ABI，公布完整函数签名、参数宽度、返回值，以及调用时需要的栈、特权级和已初始化能力。
- 内核范围使用 `__kernel_image_start`、`__kernel_image_end` 等链接符号，按 `[start,end)` 解释；end 是末端地址，不是最后一个有效字节。
- 每个范围明确是否包含 BSS、启动栈、测试代码及嵌入资源。物理页分配器排除整个加载映像，而不是只排除代码段。
- 明确边界符号在当前链接方案中表示什么地址，以及开启分页之后如何使用；不能将任意虚拟地址直接当作物理地址扣除。
- 弱默认实现只报告未实现。工程中未完成接口可以链接，不代表相关测试已经通过。

#### 实验指导书要编写什么

- C 中用函数声明调用外部函数，用 extern 声明外部变量或边界数组；说明声明不会自动把实现加入链接，我们提供的对象文件仍由 Makefile 接入。
- Rust 中使用 `unsafe extern "C"` 声明外部函数和符号，解释调用所需的 unsafe 边界；反向导出学生函数时，给出符合课程 Rust 版本的稳定符号名写法。
- 用一个最小我们提供的函数演示“声明—链接—调用—检查返回值”。再演示测试函数回调学生导出的接口，明确两个调用方向。
- 用链接脚本中 `__kernel_image_start = .;` 这样的语句解释边界符号：它标记一个地址，并不自动在该地址存放一个同名整数。获取边界时应取符号地址，不能读取那个位置的内容作为边界值。
- C 示例使用 extern 字节数组取得地址，再转为 uintptr_t 计算范围；Rust 示例使用外部符号的原始地址，避免为了取地址而构造引用或解引用。真正的外部数据变量另用一个例子说明。
- 先检查 end 不小于 start，再计算字节数；演示向外页对齐后，将整个内核加载范围加入保留区。RAM 的总范围仍由设备树取得，两种信息共同用于内存初始化。
- 用 nm、readelf、链接 map 和 GDB 对照同一符号；演示 undefined reference、名字不一致、声明签名错误及把地址误读成内容时的排查步骤。
- 普通使用优先按符号名调用。若测试确实要求固定地址，解释链接脚本如何放置代码，以及函数指针的 ABI 和调用前提；不要求学生记住地址常量，也不把任意地址强转当作通用调用方式。

#### 测试方式与覆盖范围

- 提供一个只返回固定值、不依赖 UART、页表或调度的教学函数，在 GDB 中检查确实执行到了我们提供的函数并正确返回；UART 完成后再输出该值。
- 将学生取得的内核起止地址与本次构建的链接 map 对照。地址来自当前产物，不把示例地址写成固定答案。
- 用未实现桩和学生实现分别检查链接与调用结果，讲清“能够生成 ELF”和“功能已经实现”的区别。
- 这些检查归入工程教学和早期观察，不新建通用测试运行框架，也不增加用户系统调用。
- 我们准备 C/Rust 对照示例、最小测试对象、符号表和常见错误示例。链接脚本与对象文件接入仍由我们提供。

#### 结束条件

- 结束条件为学生能调用一个我们提供的函数、导出一个被测试的接口，并解释内核地址段起止符号含义。

编写讲义时核对 GNU ld 的 Source Code Reference 与 Rust Reference 的 External blocks，具体语法以课程冻结的工具链为准：<https://sourceware.org/binutils/docs/ld/Source-Code-Reference.html>；<https://doc.rust-lang.org/reference/items/external-blocks.html>。

### 任务 3：设备树与内存发现

#### 想要让学生掌握什么

- 理解设备树描述硬件，DTS 是便于阅读的文本，DTB 是启动时传入的二进制数据。
- 能用现成库取得 RAM 起点、长度和时钟频率，不把这些值写死在内核中。
- 理解 RAM 中仍有不能分配的区域，内存发现与页分配器初始化是两项相连的工作。

#### spec 要说明什么

- 平台入口为 hart_id、dtb_ptr；设备树由学生从实际传入地址读取。
- 最小解析范围为 memory 节点的 reg、父节点的 #address-cells/#size-cells、/cpus 的 timebase-frequency，以及静态保留内存信息。
- 本版只要求一个连续 RAM 区，支持约定的 1/2-cell 编码，不要求 NUMA、热插拔、动态保留内存分配或通用设备发现。
- 可分配页从 RAM 中扣除固件、内核加载映像、DTB 本体、reservation map 和 reserved-memory 指定的区域得到；处理重叠、页对齐及地址溢出。
- 解析库负责二进制格式访问；学生负责属性含义和区间整理。缺少必需属性或范围错误时停止初始化，不继续使用猜测值。

#### 实验指导书要编写什么

- 用 dtc 展示课程实际 DTB 对应的文本，定位 memory 和 /cpus。
- 分别给出 C/libfdt 与 Rust/fdt 的查找示例，说明库接口何时返回原始字节、何时已转换数值。
- 用具体例子讲解大端编码、两个 cell 表示一个地址，以及为什么不能直接把 reg 强转成宿主整数。
- 从 RAM 区间中逐步扣除内核、DTB 和静态保留段，展示哪些完整页可以交给分配器。
- 讲解 compatible 的概念，但 UART 仍用已知板级地址，不要求本章实现驱动自动匹配。
- 说明启用分页后如何继续访问 DTB 和链接资源，以及为什么这些区域不能被释放。

#### 测试方式与前置条件

- 前置条件为工程和 UART 完成，不需要页表、调度或用户程序。
- 使用内核符号检查学生自己的解析路径；正常测试读取 QEMU 实际传入的 DTB，改变 QEMU 内存大小后核对发现结果。
- 小型公开 DTB 样本用于检查属性、编码及错误处理，不将损坏样本交给 OpenSBI 启动。
- 页分配器完成后补测保留区保护，确认分配出的页没有覆盖固件、映像、DTB 或静态保留段；不提供参考分配器。

#### 测试覆盖哪些方面

- 真实入口参数未被入口汇编改写，RAM 边界随平台配置变化。
- 按 device_type 查找内存节点，不依赖完整节点名字；正确读取 cell 和大端属性。
- 正确读取时钟频率，处理必需属性缺失、无效长度、零频率和地址溢出。
- 重叠保留区不重复扣除，页对齐不会暴露保留字节，解析失败不输出半成品结果。

#### 结束条件

- 结束条件为能解释并输出真实内存范围和时钟频率，随后在物理页模块中使用已整理的保留信息。

### 任务 4：陷阱、现场保存与第一个系统调用

#### 想要让学生掌握什么

- 理解陷阱如何保存现场，内核如何找到原因并返回原执行流。
- 自行编写陷阱入口汇编，完成 U/S 特权级切换。
- 让一段受控用户指令通过 ecall 请求最小 console_print 服务。

#### spec 要说明什么

- 系统调用参数、返回值和寄存器保存约定。
- 用户 ecall、计时器和异常的区分，返回位置如何处理。
- 少量早期探针需要的公开入口；只在确实跨测试边界传递现场时约定字段，不强制采用参考内核的完整陷阱帧和任务结构。
- 未知调用、用户异常与内核异常的行为。
- 无页表保护的用户指令仅用于早期受控实验，不满足最终用户隔离要求。

#### 实验指导书要编写什么

- 逐步解释 stvec、sepc、scause、stval、sstatus、sscratch 和 sret。
- 讲解汇编语法、栈对齐、保存顺序和用户栈到内核栈的转换。
- 从同步异常开始，再进入受控 U 态，执行一次 ecall 后返回。
- 给出 CSR 访问参考，说明来自 S 态的异常为什么不能照搬 U 态切栈过程。
- 初期探针采用固定、可信的缓冲，正式用户指针检查在地址空间建立后补齐。

#### 测试方式与前置条件

- 前置条件为工程和 UART 完成。使用内核符号检查和受控用户指令片段，暂不需要 ELF 装载器和调度器。
- 我们提供指令片段和检查数据，学生建立运行状态、保存恢复现场并处理最小系统调用。早期可在无页表保护的受控环境观察特权级切换，不用该环境运行任意用户程序。
- 后续再用用户 ELF 验证正式系统调用路径。

#### 测试覆盖哪些方面

- 多个寄存器哨兵在陷入前后保持正确，参数和返回值准确。
- ecall 返回不重复执行、不跳过额外指令，中断恢复不错误移动返回地址。
- 未知调用返回错误，受控用户异常和内核异常进入不同处理路径。
- 连续陷入与返回不会破坏栈。

#### 结束条件

- 结束条件为受控用户指令可以调用 console_print 并继续执行，陷阱汇编由学生完成。

### 任务 5：物理页管理、Sv39 与地址空间隔离

#### 想要让学生掌握什么

- 理解物理页、页表和虚拟地址之间的关系。
- 自行构建 Sv39 页表，建立独立用户地址空间。
- 理解映射权限和页面所有权。

#### spec 要说明什么

- 可用物理页与保留区、页面大小、映射范围和用户权限要求。
- 分配、释放、创建地址空间、映射、查询、撤销和销毁的外部行为。
- 页表页和数据页由谁释放，失败时哪些状态必须恢复。
- 修改活动映射后必须对后续访问生效，不规定分配器内部算法。
- 为最小系统调用提供已映射用户缓冲的范围、权限检查与复制约定，使后续 VFS 基本测试不依赖完整动态内存接口。

#### 实验指导书要编写什么

- 从一个物理页的分配和释放开始，解释为什么不能分配测试、固件和镜像区域。
- 用一个地址手算 VPN 和页内偏移，逐级构造页表。
- 说明 satp、地址翻译缓存刷新和用户权限。
- 分别讲软件查询页表和让 CPU 实际访问，不能只教“打印出的 PTE 看起来正确”。
- 展示两个地址空间相同虚拟地址保存不同内容的例子。
- 将早期 console_print 的可信固定缓冲改为受检查的用户缓冲，讲解地址溢出、跨页和读写权限；动态内存与懒分配的配合在后续内存模块扩展。

#### 测试方式与前置条件

- 前置条件为 UART 和基本陷阱处理完成。内核符号检查配合简单访问探针，在学生自己的启动和陷阱路径上运行。
- 我们提供测试数据和预期结果，学生负责页分配、映射、切换和异常报告，不提供参考映射模块。
- 集成后用用户程序再次验证隔离。

#### 测试覆盖哪些方面

- 分配唯一性、对齐、释放复用、耗尽及保留区保护。
- 页内偏移、跨页映射、权限、撤销及地址空间销毁。
- 用户不能读写内核和其他任务内存。
- 最小输出系统调用能拒绝未映射或无权限的用户缓冲，不因坏指针触发内核崩溃。
- 失败不会遗留资源，映射变更后不存在旧访问结果。

#### 结束条件

- 结束条件为能在独立用户空间实际执行受控访问并验证隔离。

### 任务 6：：最小 ELF 校验与装载

#### 想要让学生掌握什么

- 从 ELF 头和程序头找到入口、可加载段及权限。
- 将文件中的字节变成独立用户地址空间中的代码、数据、BSS 和栈。
- 建立固定用户栈和无参数入口，运行第一个完整用户 ELF；命令行参数在 shell 阶段补齐。

#### spec 要说明什么

- 只接受约定的最小静态 RISC-V ELF；不要求动态链接、共享库和其他复杂特性。
- 必须校验的头字段、文件边界、段范围、权限、入口和整数溢出。
- 文件长度与内存长度的处理、固定初始栈和无参数入口状态；基础验收不要求变长参数打包。
- 不要求解释与装载无关的节表和调试信息。
- 装载失败不能留下可调度的半成品任务，必须清理本次资源。

#### 实验指导书要编写什么

- 用 readelf 查看我们提供的最小 ELF，对应到学生需要读取的字段。
- 从一个段开始，再装入代码和数据段，解释 BSS 为什么需要清零。
- 讲清固定栈、入口地址、用户运行入口和最小 console_print/exit，直接使用之前的页分配器和页表，不要求用户动态内存接口。
- 说明嵌入 ELF 与最终根文件系统读取的区别，后续更换文件来源，保留解析和装载逻辑。

#### 测试方式与前置条件

- 前置条件为学生 UART、陷阱、页管理和 Sv39 完成。装载工程嵌入的测试 ELF，使用学生自己的核心模块运行。
- 用户 ELF 输出固定文本并退出，宿主检查输出和结束记录。此时 exit 可结束当前单任务测试，不要求多任务回收或唤醒 shell。
- 使用不同嵌入文件检查坏 ELF；需要观察装载状态时保留少量内核检查点，不建设模块替换框架。
- 完整内核阶段必须从统一根文件系统经学生 VFS 读取 ELF。

#### 测试覆盖哪些方面

- 正常静态 ELF、多个段、BSS、权限、固定栈、最小系统调用和正常退出。
- 无关节信息不影响装载。
- 错误架构、截断文件、非法段范围、无效入口和溢出被拒绝。
- 分配失败回滚，连续装载不会累积泄漏。

#### 结束条件

- 结束条件为单个用户 ELF 在 Sv39 地址空间中执行、调用系统调用并退出。这是后续用户测试的公共基础，路径与参数留到 VFS 和 shell 集成。

### 任务 7.1：用户内存接口与用户缓冲区检查

#### 想要让学生掌握什么

- 设计用户内存区间的管理方式。
- 理解用户地址不能直接当作可信内核指针使用。
- 在满足接口的前提下选择立即分配或懒分配。

#### spec 要说明什么

- brk、mmap、munmap 的参数、地址范围、权限、对齐和错误语义。
- 新内存的初始可见内容，撤销后访问行为和任务退出时的资源回收。
- 零长度、整数溢出、跨页缓冲及不可访问页如何处理。
- 允许的分配策略及各策略下的资源耗尽行为；懒分配需要说明首次访问失败时怎样结束任务或报告错误。
- 用户复制访问懒分配区域时的处理，不能让合法但尚未分配的用户缓冲直接导致内核崩溃。

#### 实验指导书要编写什么

- 先讲一种最小可行的区间管理与分配方法，再介绍懒分配的额外要求。
- 给出申请、写入、收缩、释放和再申请的完整例子。
- 解释验证整个缓冲区、复制用户数据和失败回滚。
- 说明内核处理用户缓冲的路径也需要与学生选择的分配策略配合。

#### 测试方式与前置条件

- 前置条件为最小用户 ELF 已能运行。用户测试使用学生自己的页表、装载和系统调用路径。
- 不要求先完成调度和 VFS，每次启动可以只运行一个测试 ELF，检查实际读写、保护和用户缓冲。
- 未完成调度时，致命用户异常可报告后结束本次 QEMU 测试；多任务完成后再验证只终止故障任务。

#### 测试覆盖哪些方面

- 合法申请、边界大小、重复撤销、重叠或非法请求。
- 读写权限、跨页缓冲、未映射地址和地址加法溢出。
- 不暴露之前任务的数据，退出后资源可以复用。
- 资源耗尽测试遵循对应策略的公开失败契约，不强制两种策略在相同时间失败。

#### 结束条件

- 完成我们提供的用户程序的测试。
- 懒分配属于学生可选设计，其额外调试负担不应成为必做路线的预算。

### 任务 7.2：任务、上下文切换与 round-robin

#### 想要让学生掌握什么

- 理解执行上下文、任务状态、时间片和就绪队列。
- 自行编写上下文切换汇编。
- 实现抢占、主动让出、睡眠、唤醒和退出。

#### spec 要说明什么

- 任务生命周期和调度接口，轮转、让出、睡眠与退出的可观察行为。
- 单任务、多个任务、全部任务睡眠和全部任务退出时怎样运行。
- 时间读取和睡眠单位，不用未说明的精确宿主时间验收。
- 用户异常只影响故障任务，其他任务继续。
- 退出任务的栈、地址空间和句柄的清理时机；不能释放正在使用的内核栈。

#### 实验指导书要编写什么

- 先用任务编号和注入时间实现调度策略，再接入真实上下文切换。
- 区分普通内核切换上下文与完整用户陷阱帧。
- 讲解计时器、SBI 参考调用、就绪队列、睡眠队列和 idle。
- 从两个主动让出的任务，逐步过渡到两个不主动让出的用户程序。
- 用全部睡眠和当前任务退出的例子讲清唤醒与延后回收。

#### 测试方式与前置条件

- 前置条件为最小用户 ELF 已能运行，使用学生自己的陷阱、地址空间和装载代码。
- 可用少量内核调用检查轮转队列；主要通过启动清单装入多个嵌入用户 ELF，验证真实抢占、寄存器和生命周期。
- 不依赖 VFS 或完整用户内存接口，测试使用装载时建立的固定内存；动态内存组合测试另外列出依赖。

#### 测试覆盖哪些方面

- 轮转顺序、让出、到期唤醒、睡眠期间不运行、idle 后恢复。
- 两个不调用 yield 的程序均能推进，不能用循环调用测试函数冒充抢占。
- 寄存器、栈和地址空间不串扰，退出任务不再次入队。
- 用户异常后其他程序继续，清理完成后能够再创建任务。

#### 结束条件

- 完成我们提供的用户程序的测试。
- 此阶段可由测试启动清单创建多个任务；shell 根据路径动态启动在后续接入。

### 任务 7.3：VFS 与基本文件操作

#### 想要让学生掌握什么

- 理解文件节点、每次打开的状态和每任务文件描述符表。
- 通过统一根文件系统访问程序和普通文件。
- 实现文件操作的系统调用语义与资源清理。

#### spec 要说明什么

- 文件系统后端的节点级接口、缓冲区使用方式与资源归属。
- 路径处理、open/read/write/close、文件定位、创建、删除、枚举、截断和扩容的行为。
- 访问模式、EOF、短读写、容量耗尽、无效描述符和用户指针的错误。
- 多次打开同一文件时内容共享、偏移独立的要求。
- 删除仍被打开的文件如何处理，必须选定并公开最小语义；不默认要求完整 POSIX unlink 行为。
- 多级目录和工作目录未确定前，只发布明确的最小路径范围，不用未公布路径行为验收。

#### 实验指导书要编写什么

- 解释我们提供的后端负责磁盘格式和节点存储，学生负责哪些访问状态。
- 从同一文件打开两次开始，展示偏移为什么不能放在磁盘目录项中。
- 讲解路径到节点、fd 到打开对象，以及一次跨块读写经过的层次。
- 讲解创建、截断、扩容、枚举和删除如何接到后端，怎样处理失败。
- 说明内存镜像需要可写工作区，不能误写只读的嵌入资源。

#### 测试方式与前置条件

- 前置条件为最小用户 ELF 已能运行。基本文件测试使用固定缓冲区，不依赖调度和完整用户内存接口。
- 我们提供已确定的内存块设备、后端和镜像，学生实现 VFS；这些是课程提供的组成部分，不是临时替代其他核心模块的测试环境。
- 每个测试恢复干净镜像，避免前一用例的删除影响后一用例。
- 用户程序经过学生系统调用检查文件行为；多任务文件表隔离与退出清理测试，等调度完成后再运行。

#### 测试覆盖哪些方面

- 创建后可枚举、读取、覆盖、扩容、截断和删除，其他文件不被破坏。
- 跨块读写、EOF、空文件、短读写和空间耗尽。
- 多次打开偏移独立，访问模式正确，描述符关闭后可复用。
- 非法路径、fd 和用户缓冲不会破坏文件内容或推进错误偏移。
- 删除打开文件符合选定语义，退出清理所有打开资源。
- ELF 与普通数据确实经过同一文件系统接口。

#### 结束条件

- 完成我们提供的用户程序的测试。

### 任务 8：从 shell 启动程序并等待退出

#### 想要让学生掌握什么

- 将文件、ELF、地址空间和任务管理组合为程序启动过程。
- 理解命令行参数、等待、退出结果和前台输入归属。
- 在失败后恢复可用状态。

#### spec 要说明什么

- 按路径创建并装载任务的最小接口，不需要 fork。
- 等待和退出结果如何传递，程序异常退出如何通知等待者。
- 参数长度和数量限制，以及启动失败时原 shell 不受破坏。
- stdin/stdout/stderr 的初始约定，前台期间谁可以读取输入。
- shell 恢复后仍能连续启动下一程序；后台与重定向在未确认前不要求。

#### 实验指导书要编写什么

- 跟踪一次 shell 请求从路径查找、ELF 校验、装载到加入就绪队列的过程，复用基础阶段的装载逻辑。
- 展示参数字符串和指针在用户栈中的布局，解释对齐、终止标记、长度限制与用户地址转换，再接入多个参数测试。
- 解释 shell 等待时如何阻塞、子程序退出后如何唤醒。
- 提供应用源码阅读路线，不让学生承担 shell 语法解析和编辑器移植。
- 演示正常退出、无效路径、坏 ELF、用户异常和失败回滚。
- 说明前台运行时暂停 shell 读取输入的最小方法，不引入完整终端作业控制。

#### 测试方式与前置条件

- 前置条件为学生最小用户环境、任务调度和 VFS 完成。参数打包使用已有页管理，若选择依赖动态内存接口，则先完成相应部分。
- 使用提供的 shell 与用户程序，通过 UART 注入命令并检查结果，全部经过学生内核实现。
- shell 和命令程序从根文件系统读取，嵌入测试 ELF 只保留为早期测试产物。

#### 测试覆盖哪些方面

- 带多个参数启动程序，参数内容正确。
- 前台运行期间 shell 不抢走输入，退出后可以继续操作。
- 不存在路径、坏 ELF、内存不足和用户异常后 shell 仍可用。
- 连续启动、等待和退出没有资源泄漏。
- ls、cat、rm 确实作为 ELF 被启动，不由 shell 偷换成内置实现。

#### 结束条件

- 结束条件为可以在 shell 中连续启动不同程序，并从错误运行中恢复。

### 任务 9：综合场景与资源回收

#### 想要让学生掌握什么

- 根据跨模块现象定位边界错误，解释完整用户请求的执行路径。
- 确认多次运行后的状态和资源仍然正确。

#### spec 要说明什么

- 基础演示的准确步骤、必要输入和结果。
- 创建新文件、修改已有文件、检查内容和删除均要覆盖。
- 多任务并发与用户隔离单独验收，不能由编辑器演示替代。
- 测试结果必须完整，失败、崩溃和超时不能算通过。

#### 实验指导书要编写什么

- 给出完整命令序列和预期文件结果。
- 说明模块单测通过、集成失败时应检查参数、内存复制、资源所有权和清理顺序。
- 指导学生缩小复现用例，保留有效日志，不要求长篇重复记录开发过程。

#### 测试方式与前置条件

- 用户程序与宿主 UART 脚本联合测试，使用完整学生内核。
- 基础部分的综合验收由助教查看演示过程确认结果。

#### 测试覆盖哪些方面

- 完整 shell、编辑器、ls、cat、rm 流程及文件内容。
- 重复执行、失败后再次操作、并发运行、正常退出与异常退出后的资源回收。
- 全部 case 有结果和结束记录，不能出现未完成测试却输出总通过。

### 任务 10：图形、输入与 mGBA

#### 想要让学生掌握什么

- 将已有驱动接入自己的内核，管理设备与用户程序之间的数据传递。
- 理解帧缓冲、输入事件及实际应用对内核服务的使用。
- 还包括 DMA 内存管理

#### spec 要说明什么

- 驱动要求的分配、映射、中断回调及外部 ABI。
- 帧格式、缓冲长度、提交后是否继续借用用户内存、输入事件顺序与队列边界。
- mGBA 使用的已公开系统服务及附加验收范围。
- 不把应用移植、音频、重启后存档和固定帧率作为学生要求。
- 应该提供 DMA 内存的 alloc 和 dealloc 接口。

#### 实验指导书要编写什么

- C/Rust 分别如何接入驱动，如何提供所需回调。
- 从纯色或棋盘格显示、按键事件打印，到运行 mGBA 的步骤。
- 如何区别通道顺序错误、事件丢失、用户缓冲错误和应用适配问题。
- 明确应用侧代码由我们负责，不要求学生改造 mGBA 核心。

#### 测试方式与前置条件

- 前置条件为基础内核完成。可在学生内核中用简单的内存显示记录和事件注入检查接口，不替代地址空间、陷阱和调度。
- 用户程序检查帧传递与输入，再使用提供的驱动和 mGBA 验收。

#### 测试覆盖哪些方面

- 帧尺寸、颜色和缓冲区边界，返回后修改原缓冲不会造成未约定的异步访问。
- 按下和释放、事件顺序、空队列、队列溢出后的恢复。
- mGBA 能加载 ROM、产生画面并响应实际操作。

### 待确认是否添加的任务

以下功能未确定前只列为候选，不编写必过测试，不计入基础模块时间：

- 信号量（包括其余 ipc 机制，只取信号量作代表）：若加入，教学目标为任务间同步，spec 要规定等待、唤醒和对象生命周期，测试包括有序协作、阻塞及退出清理。需要根据实际工作量决定，但考虑到进程同步也是操作系统的重要职责，因此该部分优先级较高。
- 多级目录与工作目录：若加入，补路径逐级解析、相对路径、chdir/getcwd 和任务继承测试，考虑到我们会提供完整的文件系统后端，这是可以考虑添加的任务。
- 重定向：先明确打开文件与子程序标准描述符如何关联，再决定是否加入。不能仅按 shell 增加一个语法符号估算。且如果加入重定向，就需要考虑添加维护进程 fd 表的任务，以及将 uart 的设备文件标为 stdout 的任务，这可能还需要涉及到 devfs。
- 后台任务：需要重新定义等待、退出回收和输入归属，独立评估。但是考虑到我们要做的实现非常简单，或许可以接口简单的设计为 create_process 以及 waitpid 然后不需要考虑父子进程的关系，只需要等待即可。
- shell 脚本：可先研究提供的 shell 顺序读取文件命令的最小形式，不承诺完整 sh 语法。可以考虑，视工作量而定。

设备树新增半天和外部符号练习新增四分之一天由第 7 天等缓冲时段调配，后续任务可以按实际投入顺延，不压缩其他模块的阅读和实现时间。阶段检查建议放在第 1、5、11 天，分别检查环境与 UART、最小用户运行环境和集成状态。第 7 天作为基础阶段未完成学生的补测和答疑机会。公共基础通过后，内存接口、调度和 VFS 可交换顺序；组合测试须满足列出的依赖。正式阶段要求和分值由负责人确认。

基础链条为任务 0 至任务 6，必须逐步完成。后续内存、调度和 VFS 的基本测试共同依赖任务 6；多任务文件表、动态内存与退出清理的组合测试，需要相关模块同时完成。shell 接入依赖任务和 VFS，综合验收依赖全部基础功能。

学生达到验收条件即可申请验收，不需要等到第 14 天；提前验收与阶段检查可以并存。

## 验收与评分

- 初版按测试点累计得分，允许明确的阶段依赖，具体权重待讨论确认。
- 测试及源码全部公开，不设置隐藏测试。
- 自动测试抓取 UART 结构化记录，检查用例身份、状态和结束标记，区分失败、未实现、崩溃和超时。
- 启动、UART、陷阱、首次运行用户 ELF 分别保留可验收成果；公共基础尚未完成的学生仍可获得已通过阶段的成绩。
- 后续用户测试需要先完成公共基础，不保证任意模块在空内核上获得成绩。因前置条件不足而未运行的测试单独标记，不伪装成已执行的模块失败；具体计分由评分方案规定。
- 测试必须覆盖正常行为和公开边界；实现风格、目录结构和算法选择不作为隐含评分项。
- 学生可以使用 AI 工具，原则上说明使用情况。验收时可以询问代码和具体设计，不以 AI 检测结果判定成绩。
- 附加题允许补偿基础分，具体加分和封顶规则待评分方案确定。
- 参考内核先用于内部验证，是否公开另定。

按照我们的原则，优先保证认真实现的学生可以理解和完成验收，并通过代码和设计交流了解学习情况。我们不设计严格的反作弊和反 AI 工具，仅严格拒绝硬编码输出信息欺骗测试脚本的情况。

“通过测试”表示满足当前验收覆盖的约定，不表示任意程序都能运行。

## 课程准备工作与建设计划

- 本设计方案：说明原则、范围、分工、模块和建设安排。
- spec：给出外部接口、行为、错误、资源边界和验收要求。
- 实验指导书：按天提供建议路线，公共基础逐步引导，后续模块列明依赖和测试方法。
- C/Rust 工程框架：保留真实启动参数的入口、链接、构建、工具配置和运行调试脚本；包含外部函数调用、学生接口导出和链接边界取址的教学示例。
- C/Rust 设备树解析库及裸机构建适配、设备树教学样本和内存发现测试；不包含替学生计算页池的核心实现。
- Rust 参考内核：验证全部必做要求，尽量保持最小实现。
- 少量早期内核探针、测试源码、必要对象文件、用户 ELF 和判分脚本，不提供替代核心模块的运行外壳。
- 统一根文件系统镜像、镜像制作工具、块设备与文件系统后端。
- shell、简化编辑器、ls、cat、rm 及用户库，完成自定义 ABI 适配。
- 完整 Virtio-GPU/Input 驱动接入包与移植后的 mGBA。
- 验收说明、常见问题、参考运行记录和试做修订记录。
- 一份具体的实验要求，包括要完成哪些任务，以及交付哪些实验报告。

注：参考内核使用 Rust 不等于我们只验证 Rust。我们还需要用 C 工程实际验证各测试钩子、结构体布局、预编译对象和驱动接入，保证 C 学生不需要迁移到 Rust 才能完成。

### 建设顺序

1. 冻结基础功能边界，选定统一工具环境与设备树解析库；验证库能在首次页分配前使用，以及小内存配置下固件、DTB、内核和嵌入资源没有覆盖冲突。
2. 做通公共基础全流程：工程启动、UART、设备树与内存发现、陷阱、Sv39、嵌入 ELF 装载、最小系统调用与退出，并检查每步能否观察和验收。
3. 编写 Rust 参考内核，同时完善 spec；出现接口矛盾时先改规范，不给测试添加未说明的例外。
4. 接入根文件系统和基础应用，验证完整场景，检查应用是否带入额外要求。
5. 补齐模块测试、用户测试、日志解析和 C 兼容验证。
6. 完成指导书初稿，邀请符合目标基础的学生试做。
7. 根据工作量和卡点删减任务或补充支持，冻结一套匹配的课程材料。
8. 完成图形输入和 mGBA 附加部分，单独验证，不阻断基础课程建设。
